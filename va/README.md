# 词汇助手（va）

`oks_vocabulary` 把整份词汇交出去；`va_ask` 把"说法对不上字面"这件事交给一个**常驻的词汇助手**。
助手由插件自己建、自己喂、自己收——人和主 agent 都不经手提示词。

## 怎么用

主 agent 调 `va_ask { query }`（一个说法）。工具内部：

1. 没有助手就建一个**顶层 agent**（preset `oks`、cwd 与调用方相同），把 [`1-read.md`](1-read.md)
   发过去，等它逐页读完 `oks_vocabulary`（它用的是同一份进程内索引，不重爬引用图）；
2. 再把 [`2-method.md`](2-method.md) 发过去，它回一句"准备好了"；
3. 最后发一个**握手问题**（配置 `vaWarmup`，默认问它"刚读进来的词表一共有多少条、只回数字、
   不要检索"）——它的位置就是标记：答完立刻收起，这一步确认"助手真的读完了、能答一轮"；
4. 之后每次 `va_ask` 只发一个说法，等它这一轮结束，取它最后一条回答作为**工具结果**返回。

助手的工具面在创建时就被收窄成**只有 `oks_vocabulary`**（读词表用）——检索、读节点、查数、
加载技能、问用户全部收掉：它回答只需要记忆里的那份词表，实测它一旦能检索就会去"核实"，
一次咨询从 9 秒涨到 26 秒。

助手不是子会话：回答只有工具结果这一条通道。它的会话平时处于**归档**状态（分组界面不列、模型步
被归档门挡住），被咨询时临时 `unarchiveSession`，问完再归档。首次 `va_ask` 会阻塞到装配完成
（读完 1852 条词汇）。

## 两份提示词

`1-read.md` / `2-method.md` 是助手自己的提示词，由插件在装配时直接发出去；改它们就等于改助手的
行为，不需要主 agent 或人跟着改什么。

## 助手的权限

插件在创建助手时**显式钉住**它的权限，不跟部署默认走：`sandbox/mode = read-only`（它只读词表，不写
工作区）、`approval/policy = never`（内部会话不弹审批）。两个事件都带 `source: 'delegation'`，表示
这是创建时播下的覆盖，而不是用户后来手动切的。

## 插件侧的三个配套机制

- **收起由插件主动做**：每次拿到回答后（助手此刻是 idle）把标记之后的表面节点收进一个固定文本的
  用户消息；万一那一刻有回合在飞，就留到下一次提问之前补收。助手每轮只看到「词汇 + 工作方法 +
  标记 + 当前这个问题」，会话日志保持 append-only，标记节点用 `sourceEventSeqs` 记录遮蔽范围。
- 检索层缓存在进程内按 artifact sha 共享：助手与主 agent 用同一份词汇表与反向引用图。

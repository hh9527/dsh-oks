# 词汇助手（va）

`va_ask` 把"说法对不上字面"这件事交给一个**常驻的词汇助手**。
助手由插件自己建、自己喂、自己收——人和主 agent 都不经手提示词。

## 怎么用

主 agent 调 `va_ask { query }`（一个说法）。工具内部：

1. 没有助手就建一个**顶层 agent**（preset `oks`、cwd 与调用方相同）；
2. 把**一条提示词**发过去：就是 [`prompt.md`](prompt.md)，插件在它的 `<!-- 词表 -->` 处插入
   **整份词汇**（用同一份进程内索引渲染，一行一条、无分页），它回"准备好了"——模型不搬运、
   不翻页、不检索，也不需要回答任何"读完了吗"的盘问；
3. **那条提示词就是标记**：它之后的一切（那句"准备好了"，以及此后每轮的问答）在拿到回答后
   都收回到它后面。所以表面上永远不留"没被回答的问题"；
4. 之后每次 `va_ask` 只发一个说法，等它这一轮结束，取它最后一条回答作为**工具结果**返回。

助手的工具面在创建时就被收成**空的**——它一个工具都不需要：词表是插件渲染好直接喂进去的，
检索、读节点、查数、加载技能、问用户全部收掉。实测它一旦能检索就会去"核实"，一次咨询从
9 秒涨到 26 秒；而让它自己用工具翻词表，还会按条数算术翻页漏读。

助手不是子会话：回答只有工具结果这一条通道。它的会话平时处于**归档**状态（分组界面不列、模型步
被归档门挡住），被咨询时临时 `unarchiveSession`，问完再归档。首次 `va_ask` 会阻塞到装配完成
（读完 1852 条词汇）。

## 两份提示词

`prompt.md` 是助手自己的提示词（提到"A 是封闭集合、R 只能来自 A"、输出格式与规则），由插件在
装配时直接发出去；改它就等于改助手的
行为，不需要主 agent 或人跟着改什么。

## 助手的速度旋钮

答案现在是"一行一个字符串"，长度已经不是瓶颈；一次咨询剩下的时间几乎全在模型的**推理**上。
助手**默认 `off`**（关掉思考——它的活儿是从封闭集合里挑字符串、标注出处，格式已锁死，
不值得花思考 token；实测时间 ≈ 输出 token × 3.9 ms，其中一半以上是看不见的思考）。想改就在
profile 里给插件配置 `vaReasoningEffort`（档位 id 由模型适配器定义，插件只透传）：`low` 留一点
思考，`inherit` 跟着部署/模型默认走。

## 助手的权限

插件在创建助手时**显式钉住**它的权限，不跟部署默认走：`sandbox/mode = read-only`（它只读词表，不写
工作区）、`approval/policy = never`（内部会话不弹审批）。两个事件都带 `source: 'delegation'`，表示
这是创建时播下的覆盖，而不是用户后来手动切的。

## 插件侧的三个配套机制

- **收起由插件主动做**：每次拿到回答后（助手此刻是 idle）把标记之后的表面节点收进一个固定文本的
  用户消息；万一那一刻有回合在飞，就留到下一次提问之前补收。助手每轮只看到「词汇 + 工作方法 +
  标记 + 当前这个问题」，会话日志保持 append-only，标记节点用 `sourceEventSeqs` 记录遮蔽范围。
- 检索层缓存在进程内按 artifact sha 共享：助手与主 agent 用同一份词汇表与反向引用图。

# 验收题：一次真实的词汇助手咨询

把下面「题目」整段发到一个**「OKS 问数」预设**、工作区为 `/home/h00629578/ws/oks-demo` 的会话里。
不需要贴任何提示词：词汇助手由插件自己建立、自己喂、自己收。

**发起前先确认 preset 选对了**：这个会话的工具面里应该有 `oks_search` / `oks_query` / `va_ask`。「OKS 问数」这个 preset 不挂文件与 bash 工具——**看到 `bash` 或 `read` 就是选错了 preset**，
那样 agent 手里没有知识服务，只会去翻文件。（会话头里的 `agentPreset` 字段不代表实际组合，以工具面为准。）

---

## 题目（整段发给会话）

上个月我们网络里「丢包」和「端口压力」都不太对。帮我看两件事：

1. 收包错误最多的 5 个接口是哪些（按平均值排）；
2. 这些接口入方向端口利用率最高的时段是哪些。

口径要写清楚：用的是哪个**声明过的**指标、时间窗是什么、怎么聚合的。

「丢包」「端口压力」不是词表里的字面说法——各调一次 `va_ask` 咨询词汇助手（第一次会比较慢，
它要把整份词汇读成自己的记忆）。它给的是**线索**：逐字拿去 `oks_search`、用 `oks_info` 读节点
自己的声明，再决定口径，最后用 `oks_query` 出数。别把它的候选当结论。

---

## 为什么挑这两个说法

- **丢包**：字面上一条都对不上，但真实对手方有好几类——`interface_in_errors`（平均接口接收错误包数）、
  `interface_out_errors`（发送方向）、`ap_radio_packet_loss_rate`（真正的丢包率，但属
  `source_NetworkApRadioKPI` 射频侧，另有 max/min），以及同一数据集里的原始采样维度
  `interface_kpi__ifInErrors`。方向、计数 vs 率、采样 vs 聚合、总体，四个维度都能被摆出来。
- **端口压力**：俗称。`interface_kpi__ifInBandRate` / `ifOutBandRate` 的别名里就有「端口利用率」，
  但它们是**采样维度**；声明过的聚合是 `interface_in_band_usage_avg/_max/_min` 与
  `interface_out_band_usage_avg/_max/_min`——正好逼出"聚合由查询表达"。

---

## 验收要看什么

1. **`va_ask` 是请求-响应**：两次调用各自在**工具结果**里拿回候选（不是作为一条消息）；没有多余的
   投递；第一次调用包含装配（渲染整份词表并放进助手的系统提示词），因此比第二次慢一点。
2. **助手自己的会话**（`session-va-*`）：**装配不发任何消息**，词表在助手的**系统提示词**里
   （`oks:vocabulary` section，`interpolate: false`）；每个说法才是一次回合，拿到回答后表面上的
   节点全部收进一个固定文本的标记，模型每次只看到「系统提示词里的词表 + 一个标记 + 当前这个说法」；
   被收起的问答仍在 append-only 日志里，标记节点的 `sourceEventSeqs` 列全遮蔽范围。
   助手**零工具调用**（它没有任何工具）、**不报任何数字**（条数之类的全局事实不由它给），
   回答是**一行一个字符串**，每个字符串逐字来自词表；
   推理档位是 `off`。
3. **归档**：咨询结束后助手会话处于归档状态（分组界面不列）；下一次咨询前它被临时恢复。同一个
   主会话的第二次 `va_ask` **复用**同一个助手（不重新装配）。
4. **主会话的答案**：用的是**声明过的**度量（接口侧的 `interface_in_errors` /
   `interface_in_band_usage_*` 这类），不是自己算的；"上个月"用 `time_now`/`time_calc` 折成绝对边界
   并落在数据窗口（2026-09-01T12:00Z–2026-10-03T12:00Z）内；给的是实际行而不是查询语句；口径
   （分组、聚合、过滤）交代清楚；`va_ask` 给的字符串被拿去 `oks_search` / `oks_info` 核过。

# RFC 0011：投影模式——用 JSON 方言稀疏化读类回执

- 状态：**已交付**（完成实现、隔离验收与真机体验，经授权合入 `main`）
- 立项：本 RFC；实现跟踪 [issue #35](https://github.com/hh9527/dsh-oks/issues/35)。
- 实施分支：`feat/0011-projection-pattern`（交付后清理）
- 创建日期：2026-10-16
- 关系：建立在已合入的 [RFC 0010](./0010-knowledge-jq.md) 之上（`kq` 与知识自描述装配）。
  初始范围：**不动**求值器（`crates/oks-wti`）与其 ABI、不动知识装配与知识服务契约、不动数据加工与报告契约；
  增加独立的 JS 投影公共函数，并给「读」类工具增加一个 `project` 参数。

## 体验阶段调整

- 知识图改为单一的 key → 条目 dict，原始节点保留既有 `type` 与全文；内置 `guide` 是 `Index` 类型的引导条目，默认 `kq({})` 读取 `.guide`。
- 发现契约置于 `.guide.detail.discovery`，领域入口仍是原始 `.index` 条目；内部 `guide` 与原始 key 冲突时显式报错。
- 先撤下 `oks_info` 工具及其提示词入口，节点读取统一用 `kq`。下文关于 `oks_info` 的设计保留为最初方案记录，本轮体验仅暴露 `kq` 的投影能力。
- 根据真机反馈，对 jaq 运行时错误增加 4 KiB 的格式化预算（含截断标记），在 Rust 写出时提前停止；加载与编译诊断保留原有定位，Wasm ABI 保持不变。
- 最终验收：TypeScript 类型检查、公共投影单测、Rust 诊断单测、实际 Wasm 错误与生命周期检查通过；实际宿主 schema/SDK 检查及隔离冒烟 455 项通过。

## 一、动机与范围

### 现状

`oks_info` 按 key **整读**一个节点，回执受 16 KiB 预算约束（[RFC 0010](./0010-knowledge-jq.md) 的工具契约）。
节点本身大于预算时，这一维没有出路：数据在服务里读得到，却交不到模型手上。

实测（2026-10-16，三场会话、两个模型）：

- `Dataset/current_alarm` 的声明是 **17,204 字节**，三场里各被拒一次；
- 绕法有两种：`oks_search` 按 `dataset` / `kind` 枚举成员（强模型，一步），
  或枚举 + 逐条读小节点 + 另写一个 `kq` 程序（弱模型，三步）；
- 两者都够不到**声明字段**（`detail.field_roles`、`time_roles`、`grain` 这类），
  遇到以声明字段为主的节点，当前没有低成本出路。

### 手写 jq 投影的代价

当前唯一的稀疏化手段是把程序写进 `.work/*.jq`，再以 `byFile` 执行：

- 每次投影是**两次往返**（写文件 + 调用）；实测一场演示会话写了 31 个程序，**每个只用一次**；
- 实测程序语义错误（类型、空值）集中在弱模型：两场分别 8 次与 3 次，强模型两场是 1 次与 0 次。
  也就是说这类失败会随模型变强而减少，而"两次往返"与"每个程序只用一次"是结构成本，与模型无关。

### 范围

给「读」类工具（`oks_info`、`kq`）增加 `project` 参数：用一份 **JSON 方言**声明"保留哪些子结构"，
宿主通过公共函数直接处理已装载的 JSON 数据。于是：

- 不新增工具、不改求值器与 ABI；
- 参数是纯 JSON，不再有"jq 语法嵌在调用 JSON 里"的失败面；
- 合法模式对任意 JSON 类型都有定义，缺失键和类型不匹配按第二节处理；结果仍受输出预算约束。

本次只增加读类投影；筛选、排序、聚合、下标和改名仍通过 `byFile` 的 jq 程序表达。
`jq_transform`、`create_data`、报告与来源链契约保持现状，沿用现有输出预算。

## 二、投影模式

### 语法

```
Pat := "*"                                                    // 整段保留
     | "$shape"                                               // 用形状描述代替这一段
     | "{" [ <lit> ":" Pat ("," <lit> ":" Pat)* ] "}"          // 逐字面键，允许空对象
     | "[" Pat "]"                                           // 展开一层
```

`<lit>` 是 JSON 对象键，输出键与源键同名，**一律按字面键理解**（没有通配键：
`{ "*": … }` 指的是名字就叫 `*` 的键）。`[]`（零项）与 `[a, b]`（多项）都不是合法模式。

### 语义

| 模式 | 结果 |
| --- | --- |
| `"*"` | 当前值整段保留 |
| `{ "a": Pat, … }` | 对象 → 仅保留模式列出且实际存在的键，对各键的值递归应用对应模式；数组、null 或标量 → 原值不变 |
| `{}` | 对象 → `{}`；其他类型 → 原值不变 |
| `[ Pat ]` | 数组 → 对每个元素套用 `Pat`；对象 → 对每个值套用 `Pat`（键保留）；null 或标量 → 原值不变 |
| `"$shape"` | 用形状描述代替当前值（第三节） |

普通投影保留选中的原始子结构，不做业务计算或生成业务值；`"$shape"` 是例外，它生成形状摘要，
不保证结果比原值更小。`[ Pat ]` 保留容器的全部键或元素，只对各值递归投影，不负责筛选或截取。

合法模式在每个输入值上恰好产生一个结果，不因键缺失或输入类型不匹配而报错。
对象剪枝靠“不写这个键”实现；已存在且为 `null` 的键仍会参与投影：普通模式保留 `null`，
`"$shape"` 则将它替换为 `{ "type": "null" }`。缺失键保持缺失。
类型不匹配时原值通过，因此误判类型可能保留比预期更多的内容，最终仍须检查输出大小。

非法模式在创建投影函数时报错并定位到模式中的位置；拼错但语法合法的键会被当作缺失键省略。
需要确认位置、字段或类型时，可以先用 `"$shape"` 探测。

### 例子

```json
{ "type": "*", "description": { "label": "*", "summary": "*" }, "links": "*" }
```

保留 `type`、`description.label`、`description.summary`、`links` 四段，其余丢弃。

```json
{ "documents": [ { "type": "*", "links": "$shape" } ] }
```

`documents` 是"key → 节点"的对象：键全部保留，每个节点只留 `type`，`links` 换成它的形状描述。

## 三、形状探测

`"$shape"` 把当前位置的值换成一份**形状描述**：

| 当前值 | 产出 |
| --- | --- |
| object | `{ "type": "object", "size": <键总数>, "keys": [前几个键] }` |
| array | `{ "type": "array", "size": <元素总数> }` |
| string | `{ "type": "string", "size": <字符数> }` |
| number / boolean / null | `{ "type": "number" \| "boolean" \| "null" }` |

- `size` 是总个数，不是字节数；字符串按 Unicode 码点计数（不是 JS `.length` 的 UTF-16 单元数）。
- 对象的 `keys` 按 JS 默认字符串排序（UTF-16 单元字典序）取前 `N` 个，`N = 20`，键名原样保留。
- 限制键数量只能控制摘要的条目数；单个超长键、多处探测或容器展开仍可能使回执超限。
  取键排序与字符串计数也可能随输入规模增加开销，探测不承诺常数时间或必定小于 16 KiB。
- 例如 `{ "documents": "$shape" }` 的投影结果为
  `{ "documents": { "type": "object", "size": 2782, "keys": [...] } }`，
  保留 `documents` 外壳，据此决定是否继续展开及使用什么模式。

探测同时是**自检入口**：想确认某个位置到底是什么（对象？数组？字符串？）就探一下，
不必先把整段读回来。

## 四、公共投影函数

投影在宿主侧用 JS 递归处理 JSON，实现为独立的公共函数：

```ts
type JsonValue =
  | null | boolean | number | string
  | JsonValue[]
  | { [key: string]: JsonValue };

type ProjectRule =
  | '*'
  | '$shape'
  | { [key: string]: ProjectRule }
  | [ProjectRule];

function createProjector(
  project: ProjectRule,
): (value: JsonValue) => JsonValue;
```

`createProjector` 先完整校验规则，非法规则报错并带规则位置，例如 `$.documents[0].links`；
合法规则生成可复用的投影函数。返回函数按第二、三节处理任意 JSON 值，每次返回一个 JSON 值，
保持输入数据与规则不变。对象寻址只读取自身属性，输出键按字面原样保留。

该函数只负责规则校验和数据投影；工具层负责选择输入、封装回执及检查输出大小。
`oks_info` 与 `kq` 共用此函数，投影过程直接访问宿主内存中的数据，不经过 jq 或 Wasm。

## 五、工具契约

- `oks_info({ key, project? })`：`project` 作用于该节点的声明本体（服务返回的 Found 文档，
  即 `Schema/syntax/knowledge/node` 声明的 `{key, type, description, links, detail}`）；
  缺省时保持整读，渲染方式不变。
- `oks_info` 给出 `project` 时，用 `createProjector(project)` 返回的函数投影 Found 正文，再将结果放回回执中的原位置；
  原文不另附副本。服务返回非 Found（`NotFound` 等）时按现状报告，不进入投影。
- `kq` 的 `project` 与 `byFile` 二选一；同时提供时明确报参数错误。调用方式如下：

| 调用 | 行为 |
| --- | --- |
| `kq({})` | 返回知识对象的自述入口 `K[K.index]`，保持现有结果 |
| `kq({ project })` | 对宿主已装载的完整知识对象执行 JS 投影，返回 `{ok: true, outputs: 1, data: 投影结果}` |
| `kq({ byFile })` | 在完整知识对象上执行 jq 文件程序，沿用现有值流与回执语义；需要投影时在程序内表达 |

`project` 省略表示不投影；显式 `null` 是非法模式，`"*"` 表示恒等投影。
例如 `kq({project: "*"})` 请求完整知识对象，仍可能因输出超限而失败。

给出 `project` 时，先在 JS 中完成投影，再对最终回执检查现有 16 KiB 预算；
超限报告实际字节数，不返回半份成功结果。jq 文件程序的输出限制与错误机制保持现状。

非法模式在创建投影函数时报错并定位；合法模式不因输入类型或键缺失报错。
知识读取失败、文件程序错误、超时和输出超限仍分别沿用现有错误机制。

## 六、验收建议

| 场景 | 期望 |
| --- | --- |
| `oks_info({ key: "Dataset/current_alarm", project: … })` | 回执小于 16 KiB，且所需字段与整读同源 |
| `kq({ project: { "documents": [ { "type": "*" } ] } })` | 2,782 个键都在；超限时按现有方式拒绝并报出字节数 |
| `kq({ project: { "documents": "$shape" } })` | `data` 为 `{ "documents": { "type": "object", "size": 2782, "keys": [...] } }`，`outputs` 为 1 |
| 对象模式遇到缺失键 / 已存在的 null 键 / 标量或数组 | 分别为：键不出现 / 递归应用子模式（普通模式保留 null，`"$shape"` 生成摘要）/ 原值通过 |
| `{}` 作用于对象 / 数组 / null | 分别为 `{}` / 原数组 / `null` |
| 字面键包含点号、引号、反斜杠或换行 | 按完整原名读取自身属性，键名原样保留 |
| 非法模式（`[]`、`[a, b]`、`"label"`、`"$foo"`、`null`） | 创建投影函数时报错并定位到模式中的位置 |
| `kq({})` 与 `kq({project: "*"})` | 前者仍读自述入口，后者请求完整知识对象并受输出预算约束 |
| `kq({ byFile, project })` | 明确报参数错误 |
| 已装载知识大于 jq 引擎输出上限，但 JS 投影回执小于 16 KiB | 返回完整投影结果，投影过程不调用 jq 引擎 |
| 同一投影函数重复处理不同输入 | 结果符合规则，输入数据与规则保持不变 |
| 字符串包含补充平面字符（如 emoji） | `$shape.size` 按 Unicode 码点计数 |
| 单个超长键或多处 `$shape` 使回执超限 | 按输出预算拒绝；不承诺摘要必定小于 16 KiB |
| 展开的扇出使投影回执超限 | 按现有 16 KiB 预算拒绝并报告实际字节数 |

验收方式：覆盖公共函数的规则校验与投影语义，并扩展现有插件冒烟（隔离工作区，不更新运行环境）。

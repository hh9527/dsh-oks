# RFC 0013：以 Markdown 为回答源码，全量求值数据处理流水线

- 状态：实现完成，隔离回归与真机验证通过；标准流程工作分支为 `feat/answer-draft-runtime`，待人工验收，未授权合入 main。
- 跟踪：https://github.com/hh9527/dsh-oks/issues/38。
- 创建日期：2026-10-19。
- 关系：复用 RFC 0005 的来源链、RFC 0008 的报告表达与读取，以及 RFC 0012 的数据加工能力；与 RFC 0014 的知识发现边界衔接。

## 一、动机与范围

目前，Agent 把业务思路留在会话中，把 Intent 放进工具参数，把 jq、XHTML 写成独立文件，
再手动搬运校验键与资产路径。修改分析时，还需自行判断哪些结果需要重新计算。

拟引入一份 `.work/<问题名>.md`，作为回答一个用户问题的源码。
Agent 探索、修改整份源码，工具全量求值其中的处理流程，逐步缓存并返回反馈。
文档允许只有计算、暂时没有最终答案；形成答案后，普通文字回答和持久化报告共用计算与来源。

这份源码从业务问题寻求答案，组织“问题理解 → 分析方法 → 数据证据 → 结论与表达”。
领域知识、模型和工具的学习与发现属于 Agent 的准备活动，留在业务回答源码之外。
看到业务数据后新增查询、调整口径、检查中间值或进一步分组，都通过改稿表达。

目标职责是：编辑 Markdown 定义计算，运行 Markdown 执行计算并管理产物，`oks_data` 只读取已有输出。
查询、加工、调试计算、保存和渲染由文档中的处理流程表达；读取中间结果不触发计算或写入。
这是本文拟议的工具边界，现有工具的迁移和兼容细节仍需补齐。

## 二、文档分为 pipeline 与 assets

`pipeline` 用小型表达式语言连接处理步骤，Markdown 散文说明问题理解、分析理由和表达思路。
JSON 结构通过 object constructor 等字面量直接写在 pipeline 中；assets 承载需要独立语言解析的 jq 和 XHTML 正文。

- `## pipeline` 节下有一个 `js` 代码块，定义本轮完整处理流程。
- `## assets` 节下，每个 asset 通过代码块的 `name="..."` 属性命名。
- Intent、给定数据、参数和图表规格直接内联；jq、XHTML 正文在具名代码块中按原始语法书写。

工具按 Markdown 语法树识别区域、围栏与章节，不扫描代码内容猜测区域边界。
第一版要求一个 pipeline 区域；引用具名 asset 时要求一个 assets 区域。
只有内联计算、没有 asset 引用的探索稿可以省略 assets 区域。
pipeline 的 `js` 标记用于语法高亮，实际允许的语法由第三节定义。
普通代码示例可写在其他章节，不进入流程；assets 下的具名代码块作为资产解析。
围栏长度遵循 Markdown 规则，正文含围栏字符时可以使用更长围栏。

### 从探索开始的结构示例

以下示例展示“查询 → 检查中间值 → 计算摘要”，尚未生成最终答案。
`<dataset id>` 须替换为领域声明的实际数据集，Intent 仍须通过实际模型校验。
`warningRows` 是分析参考参数，不是查询服务的行数限制，也不是观测事实。

````md
# 本次查询的数据概览

先看本次返回规模，再判断是否需要进一步分组。
这一行数只描述查询结果，不代表源数据总量。

## pipeline

```js
// 设定本次分析使用的参考阈值。
let threshold = data({ warningRows: 100 });
// 读取一批业务数据，了解后续分析的输入。
let facts = query({
  op: "Graph",
  root: "d",
  nodes: [{ id: "d", entity: "<dataset id>" }],
  edges: [],
  select: [],
  limit: 500
});
// 查看本次返回的少量数据。
debug(jq("peek.jq", { facts }));
// 统计本次返回行数，并与参考阈值比较。
let summary = jq("summary.jq", { facts, threshold });
debug(summary);
```

## assets

### 查看样本

```jq name="peek.jq"
.facts.rows[:5]
```

### 汇总方法

```jq name="summary.jq"
(.facts.rows | length) as $count
| {rowCount: $count, exceedsReference: ($count > .threshold.warningRows)}
```
````

形成答案时，在 pipeline 中补充：

```js
// 用有来源的数字说明本次查询规模。
let answer = render_html("answer.xhtml", { summary });
```

并在 assets 中补充：

```xhtml name="answer.xhtml"
<article>
  <p>本次返回 <span data-oks-ref="summary" data-oks-pick=".rowCount"></span> 行。</p>
</article>
```

一次修改可以只变更一个 asset，也可以调整 pipeline 的分析路径；工具始终处理整份源码。
jq 和 XHTML 正文独立保存于代码块中，pipeline 按名字引用它们。

## 三、最小语法与依赖

### let binding、debug、object constructor 与 project

流水线的结构语法围绕四种构造展开：

| 构造 | 示例 | 含义 |
| --- | --- | --- |
| let binding | `let facts = query({ ... });` | 将表达式结果绑定到不可变名字 |
| debug | `debug(jq("peek.jq", { facts }));` | 将表达式结果声明为供查看的输出 |
| object constructor | `{ facts, rows: facts.rows }` | 构造具名输入或内联参数对象 |
| project | `facts.rows[0]` | 从已有值选择静态路径 |

query、jq、render_figure、render_html 等是工具提供的固定算子，操作签名由协议定义。
表达式的叶子包括绑定引用和 JSON 可表达的字面量：字符串、数字、布尔值、null、数组与对象。
内联 Intent 所需的数组和嵌套对象属于值构造；筛选、遍历、条件、算术和聚合写在 jq asset 中。

每个 binding 的名字在当前流水线内唯一，先定义后引用。
绑定可以引用算子结果、已有绑定的投影或构造值；debug 可以查看绑定、投影或嵌套的固定算子表达式：

```js
let facts = query({ /* 内联 Intent */ });
debug(facts.rows[0]);
debug(jq("peek.jq", { facts }));
let summary = jq("summary.jq", { rows: facts.rows });
```

debug 无需起 binding 名，多个 debug 通过本轮源码位置关联输出。
文档没有答案节点时，照常执行全部 binding 和 debug，返回探索反馈。
答案绑定的交付选择规则仍需补齐，尤其是同时存在多个 render_html 结果时；示例以 answer 命名，不赋予该名字隐式语义。

这是一种借用 JS 熟悉写法的小型语言。解析器生成带原始 Markdown 位置的 AST，
校验允许结构后可编译为 JS 节点定义，也可直接解释执行同一 AST。
输入文本始终先按本语言检查，编译产物调用工具提供的运行时算子。
完整词法、语法和固定算子签名仍需补齐；首版语法围绕上述四种构造保持精简。

### 变量引用与静态投影形成依赖

例如 `jq("a.jq", { d1, d2 })` 中，变量引用 d1、d2 自动形成上游边，
对象的键同时定义程序输入为 `{d1: d1.data, d2: d2.data}`。
用 `{ facts: d1 }` 时，程序通过 `.facts` 访问同一份数据。
数据加工省略输入对象或传 `{}` 时看到空对象。

输入对象也可以直接投影上游数据：

```js
let a = jq("a.jq", { d1: d1.a[0].a, d2 });
```

路径以节点的 `.data` 为起点，因此上式程序看到的是
`{d1: d1.data.a[0].a, d2: d2.data}`，依赖仍是 d1、d2。
静态路径支持字段访问、字符串字面量键和非负整数数组下标，如 `.a`、`["a"]`、`[0]`；
字段缺失、数组越界或容器类型不符时明确报错，不把取值失败悄悄转成缺失输入。
下标与键在解析时固定。project 选择值时，运行时同时保留原始上游及实际取值路径。

流水线中的输入投影直接由表达式表示，需要形状摘要、过滤或取样时使用 jq。
工具从表达式构建依赖，不扫描 jq、XHTML 或散文猜测依赖，也无需 Agent 额外填写依赖清单。
顺序绑定排除前向引用与循环，非法引用在执行前定位到 pipeline 中的原位置。

三个名字空间各有职责：

| 名字 | 作用 |
| --- | --- |
| binding 名，如 facts | 当前流水线中的结果身份 |
| 输入对象键，如 rows | jq 输入或模板绑定所见的名字 |
| asset 名，如 summary.jq | 当前文档中独立语言正文的引用身份 |

同一个 asset 可以被多个表达式使用，形成不同输入的处理。
binding 名、asset 名和 debug 的源码位置都不直接充当计算缓存键或来源链节点 ID。

### 编译为带依赖的执行节点

例如 `let fact = query({ ... });` 可以编译为 `fact: ctx => query(ctx, { ... })`。
需要调度、检查和缓存时，将依赖直接融入节点定义；具名 asset 的解析／编译检查也作为依赖节点。
下面是内部编译结果的概念形状，非新增的 Agent 调用协议：

```js
{
  bindings: {
    fact: {
      deps: {
        intent: validateIntent({ /* 内联 Intent */ }, modelEnvironment())
      },
      run: (ctx, { intent }) => query(ctx, intent)
    },
    summary: {
      deps: {
        program: asset("summary.jq", "jq"),
        fact: binding("fact")
      },
      run: (ctx, { program, fact }) => jq(ctx, program, { fact })
    }
  },
  debug: [
    {
      deps: { value: binding("summary") },
      run: (ctx, { value }) => debug(ctx, value)
    }
  ]
}
```

这里的 validateIntent、asset 和 binding 表示依赖描述，构图时不执行查询。
运行器先处理可提前完成的检查，再调度业务节点。
依赖中同时表达上游结果、asset 检查和相关环境；源码位置附在节点及表达式上，用于反馈和诊断。
注入算子的输入逻辑上是 `.data` 值，来源身份和投影路径由运行时带外携带。
查询、jq、渲染可异步执行，运行器负责等待依赖就绪，缓存及失败传播也由运行器控制。
嵌套在 debug 中的 jq 同样拥有 program 与数据依赖，并参与检查和缓存。

## 四、固定算子与 assets 契约

固定算子组合现有业务能力：

| 操作 | 参数表达 | 输入与结果 |
| --- | --- | --- |
| `data({ ... })` | 内联数据值 | 给定值、参数、假设或演示数据，产生带来源的数据结果 |
| `query({ ... })` | 内联 Intent | 内部校验并只读执行，产生含 `{rows, columns}` 的查询结果 |
| `jq("a.jq", { ... })` | 具名 jq asset 与输入对象 | 接收具名数据对象，恰好产生一个 JSON 值 |
| `render_figure({ ... }, { data: a })` | 内联图表／表格规格与输入对象 | 复用渲染能力，生成带数据与来源的展示件 |
| `render_html("answer.xhtml", { ... })` | 具名 XHTML asset 与输入对象 | 组装答案，具名输入绑定正文的引用 |

assets 的 name 在文档内唯一，采用带扩展名的单个文件名；名字不自动解析为工作区外部文件。
jq 要求 jq 正文，render_html 要求 XHTML 正文。缺失、重名或语言错配在执行前明确报错。
内联 Intent、数据和规格由相应算子检查，不要求将 JSON 另外拆成具名 asset。
给定材料的性质进入来源记录，其精确参数形式仍需补齐；查询结果及加工值通过变量流转。

允许尚未引用的 asset 留在文档中作为备选，它们不产生业务计算节点。
先检查所有引用的 asset；同一正文重复使用时可共享检查产物。
工具可在内部适配现有文件接口，Agent 只维护这一份 Markdown。

render_figure 的数据角色由固定输入键确定：data 是主数据，关系图可选 nodes 是节点数据。
这些值是依赖表达式，运行器自动解析上游。
render_html 的对象键直接对应 data-oks-ref；标量提取继续使用 data-oks-pick。
沿用报告绑定的双向检查：正文引用须有绑定，每个绑定也须在正文使用。
模板语法和静态引用可以提前检查，动态值、shape 与标量提取在输入就绪后检查。

源数据查询、加工和展示继续遵守现有行数、输出预算、确定性及来源规则。
时间来自显式捕获的上下文材料；首版入口需在实现前明确，不能依靠 jq 读取隐式当前时间。
知识发现与词汇规整仍是业务源码之外的准备活动；只读工具边界下的知识投影和检索入口需单独明确。
模型参与查询校验与执行时的实际身份须可追踪。

## 五、全量求值与探索反馈

运行工具暂称 oks_run_answer，参数建议为：

```ts
{
  src: ".work/question.md",
  delivery?: "reply" | "artifact",
  refresh?: boolean
}
```

一次执行固定读取时的源码快照；执行中的修改属于下一轮。
delivery 默认 reply，在存在可交付答案时决定展示形式；纯探索稿返回计算反馈。
最终答案如何选择仍需补齐，不将变量名 answer 视为隐式交付指令。

执行顺序为：

1. 解析完整 Markdown、pipeline 与具名 assets，固定源码摘要。
2. 检查语法、名字、固定算子签名和资产引用，构建带依赖的执行节点。
3. 完成可提前检查的 asset 解析／编译、内联规格检查及静态 Intent 校验；命中校验缓存时复用。
4. 处理全部 binding 和 debug 表达式，命中计算缓存则复用，未命中则执行。
5. 检查动态输入、模板绑定和标量取值，返回计算、debug 与可选答案的状态。

静态结构和可提前完成的预检查错误在执行新业务计算前返回。
依赖上游业务值的 Intent 校验在输入就绪后进行，对应查询只有在校验通过后才能执行。
首版可按源顺序调度，依赖就绪后执行，后续也可按 DAG 调度独立节点。
某节点运行失败，其下游为 blocked，独立分支继续，以便一轮获得更多反馈。
失败、取消、超时和预算超限不产生成功计算缓存项，独立成功的计算可在下轮复用。

计算状态与交付状态分别表达。没有最终答案是正常的探索状态；
某个独立探索分支或 debug 失败时，仍准确报告失败，答案是否就绪由答案自身及其依赖决定。
结构校验未通过的源码不进入业务执行或答案交付。

全量求值针对整份源码，缓存是内部执行优化；Agent 通过改稿调整分析路径。
临时取样或调试加工也写进源码，例如 `debug(jq("peek.jq", { facts }))`。
小型 debug 值直接进入有界回执；大型值返回 shape 和读取引用，完整值由运行器管理。
输出呈现超预算不应把已成功的业务计算误报为失败，也不能将截断的展示冒充完整输出。
debug 的具体输出定位及分页规则见第八节待补齐边界。

## 六、校验缓存、计算缓存与数据新鲜度

### 校验也是依赖节点

asset 解析、编译、合法性检查和 Intent 校验均有独立的依赖身份，缓存可保存检查结果及编译产物。
仅名字相同不足以命中，检查器及其依赖的环境发生变化时重新检查。

| 检查 | 缓存依据 |
| --- | --- |
| jq 解析／编译 | asset 内容、编译器版本与影响编译的配置 |
| XHTML 语法与静态模板检查 | asset 内容、检查器版本、允许子集及绑定声明等实际检查依据 |
| 内联 Intent 语法／结构检查 | Intent 值、语法／结构检查器版本 |
| Intent 领域语义校验 | Intent 值、模型身份及相关配置 |
| 动态输入与绑定检查 | 检查规则及其实际依赖的输入 shape 或值 |

只依赖 shape 的规则可按 shape 缓存；依赖具体值的规则必须纳入实际值。
模型变化使领域语义校验失效，不要求与模型无关的 jq 编译一并失效。
确定性的静态校验失败也可缓存其诊断；诊断位置每轮重新关联到当前 Markdown，不能照搬旧行号。
超时、取消等暂态失败不冒充已完成的合法性检查。

### 计算复用与本轮来源装配

每个 binding 和 debug 内部的计算表达式都是可缓存单元。
计算身份依据操作、内联参数、实际程序内容、具名输入值以及相关执行环境。

- 修改 jq asset，重新检查该程序及使用它的计算，再按实际输入检查下游。
- 修改 XHTML，复用查询与加工结果，重新检查模板并组织表达。
- 仅重命名 binding／asset、调整注释和排版，计算内容及接口不变时可复用。
- 对象输入键参与计算身份：把 facts 改成 rows 是输入接口变化，即使值相同也须重新判定。
- project 完成后按实际选中的输入判断纯计算复用，未选中的数据变化不必触发该计算。
- 模型、执行器、渲染器版本或相关配置变化，使受影响的缓存失效。

实际输入值用于判断计算复用，来源身份用于验证本轮来源装配。
相同数据具有不同来路时，可以复用纯计算，但须继承本轮真实上游；不能直接返回带旧来源的最终封装。
计算缓存与运行记录分开，名字、业务说明或源码位置的变化不能伪造重新查询事实。
首版可采用保守缓存判定，允许未命中，不能错误复用。

缓存范围先限定在当前工作区、会话及同一份源码的工作状态内。
缓存须有容量与回收边界，进程重启后允许失效；不承诺跨源码或跨会话复用。
缓存所需材料已回收时，运行器可以恢复或重新执行；只读 oks_data 不承担恢复写入或重算。

### 查询按采集批次复用

相同 Intent 在不同时间可能读到不同结果，Intent 校验键只证明定义一致，不能证明数据新鲜。
首次运行创建采集批次，之后改稿默认复用该批次已经取得的未变查询结果：

- 改 jq、模板、debug 或业务说明，复用已经采集的数据。
- 改 Intent 或新增查询，在实际执行时采集并记录时间。
- refresh: true 新建采集批次，重新执行查询，再按新输入检查加工缓存。
- 模型、数据源配置等相关环境变化，对应查询缓存失效，回执说明原因。

批次表示改稿期间的复用范围，不代表数据库事务快照。
不同查询可能在不同时间取得，缓存回收后的重查也须明确标记。
显式上下文时间应在采集批次内固定，新批次重新捕获，具体入口仍需补齐。

## 七、意图与来源链

源码 DAG 描述计划怎样处理数据，origin 记录结果实际怎样取得。
每步的业务意图建议写在对应 let 或 debug 前紧邻的行注释中，工具提取关联说明。
asset 所属章节的标题和散文解释方法与表达设计；同一 asset 的多次使用可有不同业务意图。

来源链必须保留：

- 给定数据的实际内容与性质，查询实际执行的 Intent、模型身份及观察到的数据来源。
- 实际执行的 jq、业务意图，以及具名输入与完整上游。
- project 对应的上游根与实际选择路径；切片和缓存复用均保留本轮路径与来源。
- 实际使用的绘图规格、模板绑定，图表和正文标量各自的数据来路。
- 程序所属源码及 asset 名，并随来源保留实际代码，源码文件删除后仍能解释结果。

本轮运行记录保存源码摘要、binding／debug 与表达式的对应关系、结果身份和缓存复用信息。
注释、名字和位置变化时更新本轮关联，查询真实采集时间、实际来源及原始记录保持准确。
已有交付结果不会因源码继续编辑而被改写；缓存命中不能记作重新查询。

持久化报告沿用现有自足归档：最终展示数据、完整来源链，以及实际使用的 jq 共享代码。
文档的 assets 是创作资源区，报告读模型的 data.assets 是归档结构，分别保持各自职责。
报告无须携带全部备选源码、debug 输出或通用中间结果；是否附整份回答源码及自动缩水另议。

## 八、只读输出、中间结果与交付

### 按文档和 binding 读取

运行器自动管理中间结果物化和回收，Agent 用文档路径和 binding 名读取已有输出：

```js
oks_data({ input: ".work/draft.md#summary" })
```

该引用表示当前会话中这份文档最近一次运行的 summary 输出，读取自动解包 `.data`。
读取本身不运行 pipeline、不执行 project／jq 加工、不保存新结果，也不刷新查询。
需要不同取样或计算时，在源码内写 project 或 jq，并用 binding 或 debug 暴露输出。

- 尚未运行，或者最近一轮该 binding 失败、被阻塞：明确报错，不回退到更早的成功结果。
- 最近一轮已移除该 binding：按本轮运行记录报未定义，不搜索旧版本。
- 源码在运行后发生修改：可查看保留期内的已有结果，回执标明源码已修改及结果所对应的运行摘要。
- 输出或运行记录已回收：明确报不可用；重新求值由运行入口负责。

文档路径加 binding 名是便于查看的动态入口；本次读取解析到的运行身份和源码摘要须固定记录在来源中。
保存的产物不能因下次运行或改名而改指向新输出。
读取已有产物沿用只读数据访问；只读入口的完整参数、较大结果的范围读取与预算反馈仍需定义。

### debug 输出

debug(expr) 无需人为命名，运行回执通过原 Markdown 的行列位置标识每个 debug。
例如 debug(facts.rows[0]) 直接查看投影，debug(jq("peek.jq", { facts })) 计算并查看样本。
小值随回执返回，大值提供 shape 和运行器生成的只读输出引用。
`draft.md#summary` 中的片段表示 binding；匿名 debug 的读取引用格式另行确定，不把行号当稳定缓存身份。

### 普通回答与持久化报告

render_html 形成可交付的答案值，普通回答与报告共用 XHTML 数据引用和来源绑定。
纯探索稿照常返回计算与 debug 输出，不要求创建 XHTML 模板。

- delivery: reply：适配为宿主可展示的对话内容，返回给 Agent 交付，不登记 HTML 报告资产。
- delivery: artifact：输出自足 HTML 报告，按产物机制登记并返回路径。

最终答案选择和对话呈现子集需明确；不能假定宿主直接显示 XHTML。
超出呈现能力的元素须给诊断；最终文字超过预算时应调整规模或改用报告交付。
普通回答不生成报告文件，但源码、运行状态和内部数据仍可在保留期内存在。
对话结果带运行身份；持久化报告继续依靠自身内容解释来源。

### 有界回执

运行回执提供：

- 源码摘要、运行身份、采集批次、计算状态及可选答案的交付状态。
- 由依赖生成的流程摘要，各 binding／debug 的 executed、cached、failed、blocked 状态。
- 查询实际采集时间、缓存复用来源及重新采集原因。
- 适用的 shape、行数、有界 debug 输出与只读引用。
- 指向 pipeline 或 asset 原 Markdown 位置的诊断；jaq 无运行时源码位置时如实保留限制。

完整数据不逐项展开到回执。计算或查看方式的修改写回源码，oks_data 负责读取现有结果。

## 九、实施边界与验收方向

本轮拟引入业务回答编排层，并明确运行与只读查看的工具职责。
实现时应提取共享查询、加工、渲染函数，再增加 Markdown 提取、小型表达式解析、依赖图和运行状态。
解释 AST 或编译成 JS 节点均可复用同一运行时；固定算子共享现有业务能力、输入约束和来源规则。
知识发现的接入、只读 oks_data 的迁移及最终交付接口在实现前补齐。

后续验收至少覆盖：

| 场景 | 期望 |
| --- | --- |
| 只有计算的探索稿 | 无需答案模板，全部 binding 和 debug 正常求值 |
| 完整源码反复提交 | 校验与计算按依赖缓存，查询和物化不重复 |
| 内联 Intent、参数、数据与图表规格 | 值构造合法，对应算子正确校验和记录来源 |

| 缓存静态校验失败后移动代码 | 诊断命中缓存，位置仍对应本轮 Markdown |
| 重命名 binding／asset、移动 debug 或修改说明 | 内容及接口不变时可复用计算，本轮来源关联准确 |
| 同一 asset 用于多个表达式 | 检查可共享，计算按各自输入判定，意图和来源正确 |

| 来源变化而数据相同 | 纯计算可复用，产物继承本轮真实来源 |

## 十、已确认方向与待补齐细节

已确认的方向：

1. Markdown 可以只有计算，逐步从探索形成答案；知识掌握与发现留在业务回答源码外。
2. 结构语法围绕 let binding、debug、object constructor 和 project，固定算子连接业务能力。
3. Intent、数据和图表规格内联；assets 承载独立语法的 jq 与 XHTML。
4. debug(expr) 可以嵌套 jq 或直接查看 project，无需给每个调试输出起名字。
5. 依赖融入执行节点，包含 binding、具名 asset 及检查依据；合法性检查与编译产物也可缓存。
6. 每次求值完整源码，逐步复用校验与计算；改稿默认复用采集结果，显式刷新时重取。
7. oks_data 为只读入口，按 draft.md#binding 读取已有输出；计算与写入能力放在文档运行中。
8. 普通回答与报告共用模板及来源链，中间结果由运行器管理。

进入实现前仍需补齐：完整词法／语法和固定算子签名、业务意图注释的精确提取、
给定数据性质的参数、显式时间上下文入口、最终答案选择和交付规则、对话呈现子集、
匿名 debug 读取引用与大输出范围读取、只读 oks_data 的迁移及知识投影／检索入口、
校验及计算缓存预算和运行状态保留周期。
本稿记录设计方向，尚不作为可直接照做的完整协议。


## 十一、实施记录：源码前端

首阶段实现 Markdown 与 pipeline 前端，尚未注册运行工具或改变当前运行环境。
使用 CommonMark AST 识别顶层 `## pipeline` 和 `## assets`；blockquote、列表及其他章节中的示例不充当流程区域。
首版参与计算的围栏从第 1 列开始且必须显式闭合，保持代码到 Markdown 的原始行列和UTF-16 offset 映射。
源码上限为 UTF-8 256 KiB。尚未引用的 asset 不触发程序检查；重复名字、非法属性和扩展名错配属于文档结构错误。

pipeline 使用 ASCII 标识符、JSON 双引号字符串和有限数值，支持 JSON 值、数组和对象；对象键可为标识符或字符串。
数组、对象和算子参数允许尾逗号，语句必须以分号结束。允许行注释及块注释。
紧邻语句前的独立行 `//` 注释组成该步业务说明；尾随注释及隔着空行的注释不关联下一步。
对象重复键、绑定重复及前向引用在解析阶段报错。投影下标只接受字符串或十进制非负安全整数。
解析器不接受赋值、动态调用、方法、模板字符串、运算符或控制流，也不执行输入 JS。

解析结果保存 statement 与表达式位置，并为每步提取去重的上游 binding 和具名 asset 依赖。
`jq` 和 `render_html` 的 asset 参数必须是静态单文件名字，在进入执行层前检查其存在性与语言。
`context()` 预留为显式时间材料算子；具体数据契约随执行层补齐。
本阶段通过前端测试与 TypeScript 检查，不构成运行、缓存、只读结果或交付链路已完成的声明。


### jq 独立编译与引擎缓存

引擎提供 `check_program`，以运行时同一函数白名单装载和编译程序，不执行任何测试输入。
因此递归程序、依赖动态输入的合法程序及显式 `error(...)` 都能通过编译检查，运行错误仍由执行阶段报告。
检查与求值共享拥有完整图的编译产物；成功缓存按程序正文匹配，不把用于诊断的文件名当计算身份。

每个 worker 最多保留 32 个程序且缓存正文合计不超过 256 KiB，按最近使用回收；
超过正文预算的程序可以编译和执行，但不常驻。worker 释放、超时或 trap 后编译缓存随实例失效。
引擎暂不缓存编译失败；后续文档校验层缓存失败时必须按当前 Markdown 位置重定位。
本阶段隔离 Wasm 构建和既有 jq/时间回归通过，在线引擎未替换。

### 全量调度与运行记录核心

每个运行状态实例绑定工作区、会话和源码，由宿主注册表管理。开始新运行即替换最近运行记录，
因此解析失败、预检查失败、绑定失败、被阻塞或从源码移除时，不会回读旧成功结果。
同一实例同时只允许一轮执行；执行固定传入的源码文本，后续编辑只影响 stale 标识和下一轮。
独立分支继续执行，依赖失败的分支标为 blocked，取消后的未执行步骤也标为 blocked。

计算缓存只保存数据及该次计算的证据；命中后仍调用来源装配层，接入当前实际输入和投影路径。
静态投影检查自身字段、容器类型和数组边界；构造输入时记录取值在输入对象内的位置与原上游路径。
查询与 context 的缓存身份包含采集批次，refresh 清除采集项而保留可按实际新输入判断的纯计算项。
实际执行环境参与对应算子的缓存身份。

当前核心默认计算缓存 128 项／16 MiB，缓存及最近运行记录保留 30 分钟；
读操作只返回保留中的值，不刷新保留时间、不恢复材料、不执行计算或写入。
单轮保留输出另设 32 MiB 存储预算，达到预算明确报错并阻塞依赖，不登记不完整成功值。
这与后续工具回执的呈现预算不同。缓存和读取均隔离可变引用，实例释放清除结果及缓存。

此阶段使用隔离测试后端验收调度与来源约束，尚未完成真实查询、渲染和工具注册。

### 固定算子的业务后端

真实后端已连接模型 transform 校验、只读 SQLite、jq 引擎、共享图表/表格规则和 XHTML 报告组装器。
引用的 jq/XHTML 先检查，能静态取得的 Intent 和图表规格也在新业务计算之前检查；
依赖查询或 jq 输出的动态 Intent 在值就绪后校验。确定性的 asset 检查成功/失败和领域校验结果可缓存；
取消、超时及 worker 故障不作为确定性 jq 语法错误缓存。错误每轮关联当前 Markdown 位置。

`data(value, {kind: "given" | "parameter" | "assumption" | "example"})` 的第二参数可省略，默认 given；
性质、实际值和本步说明进入来源记录。`context()` 返回：

```ts
{
  utc: {epochMillis: number, epochSeconds: number, rfc3339: string},
  tz: {client: {id: string, offset: string, offsetMinutes: number}}
}
```

时间在采集批次内复用，时区沿用当轮浏览器上下文规则。RFC3339 保留毫秒并与 epochMillis 对应；
现有以秒为单位的 jq 时间函数可以直接使用 epochSeconds。

query 的结果为 `{rows, columns}`，模型身份、采集批次、实际采集时刻和查询前观察到的数据文件状态进入来源；
执行器发现额外截断时明确失败，避免后续把不完整结果当完整结果。
图表与表格在运行内生成展示件，不要求中间产物先落成 Agent 搬运的文件路径。
render_html 每轮按当前绑定组装报告的来源和归档，记录实际 XHTML 正文及源位置，
不会复用带旧来源的整页。模板标量取值和展示件绑定继续采用既有双向绑定规则。

后端测试已覆盖真实 jq、SVG、表格、XHTML、校验缓存/错误重定位、查询前校验和来源归档。
使用实际 iCloud 模型与只读 SQLite 完成查询→jq→答案集成验收，并验证只改模板不重查、refresh 重查及非法领域 Intent 不访问数据库。
当前仍是内部后端，工具注册、对话呈现、只读输出范围读取和知识发现迁移待完成。

### 工具协议与交付选择

工具注册面为 `oks_run_answer`、只读 `oks_data`、只读 `oks_knowledge`、`va_ask`、`oks_artifacts` 和五个 work_* 工具。
业务查询、给定数据、加工、时间材料、展示件和答案的生成统一在文档内表达。
旧业务写工具不注册到 Agent 工具集合。

```ts
oks_run_answer({
  src: ".work/question.md",
  answer?: "bindingName",
  delivery?: "reply" | "artifact", // 默认 reply
  refresh?: boolean
})
oks_data({
  input: ".work/question.md#summary", // 或 #debug、#debug/1、已有产物路径
  pointer?: "/rows", // JSON Pointer，仅选择已有数据的子树
  offset?: 0,
  limit?: 20, // 范围读取支持数组或对象成员；1..100
  meta?: false
})
```

默认答案候选是直接绑定 render_html 的 let 语句，名字没有隐式意义。
零个候选为探索稿，一个候选自动选择，多个候选要求显式 answer；也可显式选择保留完整答案值的绑定。
失败的答案输出返回 unavailable，而不是把文档当作没有答案。
回执分别表达计算完成/部分失败和交付状态：独立 debug 失败不阻止依赖已就绪的答案交付。
Markdown 一级标题作为答案标题，未提供时采用模板文件主干。

`#debug` 列出最近一轮的匿名调试输出及位置；`#debug/N` 读取该轮第 N 个 debug 的已有值。
JSON Pointer 和范围参数属于对固定运行结果的读取，不执行 pipeline project/jq 算子或新增来源/材料。
meta 只暴露已有来源及取值路径，不夹带生成的整页展示正文。未命名 asset、来源文件删除或实例回收不触发读取重算。

reply 将 XHTML 的标题、段落、强调、列表、代码、链接、普通表格和图转为原生 Markdown；
图写为带数据与来源的内部 SVG，回复本身不登记 HTML 报告。
合并单元格等无法可靠转换的内容给诊断，建议 artifact；回复正文预算 8 KiB，反馈另有约 6 KiB 的有界摘要。
artifact 使用同一模板绑定和来源生成自足报告，并登记已有产物机制；相同证据/源码的重复交付复用仍存在的文件。

只读知识发现独立于业务源码：

```ts
oks_knowledge({project: {datasets: {current_alarm: {fields: "Shape"}}}})
oks_knowledge({jq: {src: "builtin://knowledge/search.jq", args: {query: "current_alarm", take: 5}}})
oks_knowledge({help: "oks://help/query"})
```

project 直接作用于 `{datasets, types, relations, items}`；jq 的输入为 `{knowledge: <graph>}`。
自定义 jq 从 `.work/*.jq` 读取，内置检索以具名 builtin 程序及参数使用。
知识工具没有业务输入或 save，因而不会成为绕开文档运行的业务计算入口。

进程内最多保留 8 份工作区/会话/源码状态，按最近运行和 30 分钟保留窗口回收；读取不延长保留期。

### 方法入口、帮助与文档迁移

`time_windows(ctx, {unit,count,mode})` 是固定算子，使用显式 context 材料，
复用日历窗口 jq 方法；mode 必填，支持 complete/current/rolling，count 为 1..50。
返回值为按时间排序的窗口数组，每项包含 label、zone，以及 start/end 的 epochMillis 和 RFC3339。
静态参数错误在新业务查询前报告，实际生成的 jq 正文和 ctx 上游进入来源链，计算参与运行缓存。
月、周、季度和年边界遵守指定时区的日历规则，不通过固定时差推导。

`oks_knowledge({help:"oks://help/query"})` 返回主题索引，
`oks_knowledge({help:"oks://help/query",topic:"graph/filter"})` 读取精确主题；
topic 只用于 help，拒绝不存在或继承的属性，避免完整查询契约占满回执预算。

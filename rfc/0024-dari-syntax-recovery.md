# RFC 0024：DARI 语法诊断恢复

状态：草案。跟踪：https://github.com/hh9527/dsh-oks/issues/62

## 目标

在一次检查中报告可可靠区分的多处语法错误，并保留原始源码位置。恢复只用于诊断，不把推测补全的源码当成有效程序；存在语法错误时禁止业务读取、SQL 执行、渲染和交付。类型诊断遵循 RFC 0023，语法恢复不得产生依赖损坏语法的连锁类型错误。

当前 `dom.ts` 同时扫描顶层声明、`tree!` 和表达式边界，`typed-syntax.ts` 解析表达式；两者遇到错误均可能抛出 `DraftSyntaxError`。声明解析还会修改 definitions、nodes、references、figures、templates 和作用域，因此只跳过字符不能保证后续状态正确。

## 恢复单位与事务

第一阶段以完整顶层声明为恢复单位。每次尝试声明时建立独立的暂存状态，只有声明及其降低完成才提交定义、节点、引用、资源和作用域修改。失败时保留诊断并丢弃该声明的暂存状态；嵌套模板中的临时节点和作用域也必须回滚。资源预算和取消等终止条件不能作为普通语法错误恢复。

能够可靠识别声明种类和名称时，保留一个有原始位置的失败声明节点，表示名称已声明但内容不可用；后续引用它时传播未就绪状态，不再报告未定义名称。名称不可靠时不猜测名称或依赖；后续无法确定的名称诊断应抑制，不能伪造成功绑定。重复声明与前向引用仍按现有规则检查，但不能因恢复时丢失或猜测名称制造额外错误。

## 同步边界

扫描同步点时必须识别 JSON 字符串及转义、行和块注释、括号嵌套以及 `tree!` 范围。仅在词法状态和嵌套关系可靠时，以顶层分号结束当前声明，并从其后继续解析下一声明；分号属于同步过程，不得当作新声明起点。恢复必须消费输入或结束，避免无限循环。

未终止字符串或块注释、无法确定归属的括号失配、以及缺少终止符导致后续声明可能属于当前表达式时，不推测后面的分号或关键字为新声明。报告已确定的错误后停止当前文件的恢复。可以在将来引入经单独测试证明可靠的更细粒度同步，但不能靠换行、正则匹配声明关键字或直接搜索分号猜测边界。

初始阶段不在表达式内部或 `tree!` 子节点之间插入缺失 token，不对损坏的声明继续类型检查。合法但带非 ASCII 标识符的现有词法诊断仍保留原始范围和建议；它与其他语法错误共存时，重复诊断按统一收集器规则去重。

## 与检查和执行衔接

解析结果显式区分完整声明与失败声明，失败声明不是合法 `Expr`，也不能序列化成可执行 IR。检查模式可分析已完整解析且不依赖失败声明的节点；失败节点及其依赖列入未就绪，其他独立节点可产生类型诊断。若依赖关系因损坏源码不可知，保守地停止依赖相关检查，不推断 schema、查询参数或类型。

`dari_resolve` 和 `dari_check` 使用相同的诊断解析结果；任何错误均使整稿执行屏障关闭。严格解析入口继续拒绝带错误的结果，运行时和缓存不得接收失败节点或部分成功计划。诊断顺序、去重与公开回执上限沿用 RFC 0023。

## 验收与实施

1. 抽出可事务化的声明解析状态，并验证失败声明不遗留定义、节点、模板引用或作用域
2. 实现可证明的顶层同步及失败声明表示，覆盖多个独立声明错误、成功声明、依赖和未就绪状态
3. 验证字符串、转义、注释、嵌套、`tree!`、缺失分号、未闭合定界符和 EOF；不可靠边界只报告可确定错误，不吞掉有效声明或虚构额外错误
4. 通过真实 `dari_check` 和 `dari_resolve` 入口验证位置、稳定排序、去重、回执上限及不读取业务行、不执行 SQL、不发布结果；覆盖取消、预算和内部异常
5. 完整回归与类型检查通过后，评估是否值得设计表达式内及模板子节点恢复，另行定义其同步和错误节点，不将其视为本阶段已支持

## 当前实现

- 已在可确认分号及平衡定界符的声明边界恢复 `data`、`figure`、`report` 和 `answer`；失败声明保留名称与源码范围，独立声明继续检查，依赖错误类型的部分不产生连锁诊断
- 同一损坏声明内部仍只恢复到声明末尾，不承诺一次报告该声明内所有语法错误；缺失分号、未终止字符串或注释以及不匹配的定界符可能使恢复停止
- 资源预算和严格执行入口仍终止处理；`dari_resolve` 存在诊断时不进入业务执行和交付。回执上限、类型基准及恢复后的执行边界由专项测试覆盖
- 表达式内部或模板子节点的细粒度恢复暂不实施：需要先定义独立的错误节点及同步边界，并证明不会降低位置精度或产生连锁误报

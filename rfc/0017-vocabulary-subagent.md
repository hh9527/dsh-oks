# RFC 0017：词汇咨询使用宿主管理的子会话

状态：已验收，批准合入。日期：2026-10-22。

## 目的

词汇助手采用父会话可发现的子会话，简化执行、取消和资源释放的管理，
并让用户能在宿主界面查看咨询任务及其记录。本次不以性能收益为目标。
原有的“较大固定词表前缀 + 模型上下文不随咨询增长”策略保持不变。

## 行为

每个父会话复用一个 `spawn` 子会话，使用 `oks-vocabulary` 专用预设。
预设在系统提示词装配时按子会话工作区取得完整词表，工具面为空，
权限限定为只读和不请求审批。首次创建时由宿主继承父会话模型路由，
推理档位沿用插件的 `vaReasoningEffort` 配置；恢复时读取持久化的子会话配置。

助手沿用固定边界收起机制：保留词表所在的系统前缀，把其后的上一轮问题、
回答、运行时上下文及旧收起标记一起替换成一条固定用户标记，再接收当前问题。
第一轮也使用相同标记，确保首轮与后续轮次的输入形状一致。
收起只改变模型可见表面，追加式日志完整保留历史问答和收起来源，供宿主展示与回放。
每次模型步之前执行收起，空闲时也收起；异常中断后恢复时仍适用同一个边界。

主 agent 每次通过 `va_ask` 发起咨询。首次调用 `subagents.startActivation`，
指定 `delivery: parent`；续问使用 `subagents.sendMessage`。
工具返回子会话 ID、消息 ID 和投递确认，回答由官方宿主作为子 agent 消息送达主 agent。
主 agent 收到回答后再检索和核实其中的词汇线索。
宿主负责执行、结束通知、中断和释放，父会话恢复后通过 `listChildren` 找回原子会话。

同一父会话同时咨询相同问题时共享一次投递；不同问题等待前次 `subagent/end` 后投递。
词汇数据仍使用现有模型索引缓存。插件卸载后拒绝排队请求；已受理咨询由宿主继续管理。

## 实现范围

只修改 dsh-oks；运行在官方 DSH `0.2.1-rc.2` 上，不修改或部署宿主源码补丁。
安装器注册专用预设，普通 OKS 插件提供 `va_ask`；助手模式装配提示词、
权限及固定边界收起，不注册业务工具。现有独立助手会话的历史记录保留。
原插件的 `vaAskTimeoutMs` 执行超时配置退出，子会话执行与中断使用宿主原生机制。

此前分支采用“每次咨询新建子会话”，现改为复用单一子会话并恢复原有收起机制。
曾尝试增加同步续问的宿主 API；该方案撤回，最终采用原生子 agent 消息投递。

## 验收

- 8 项词汇助手测试覆盖首次创建、续问、目录恢复、并发合并、串行投递、独立父会话、
  推理档位、取消入队、失败重试、卸载、词表装配，以及 100 轮收起后上下文恒定、日志完整。
- 官方宿主、隔离 headless profile、本地确定性适配器和真实模型词表验证：
  连续咨询、父会话释放后恢复、模型失败、中断和重试，始终复用一个词汇子会话；
  主 agent 原生接收回答，子会话上下文只保留固定前缀、固定标记与当前问题。
  共 16 次模型咨询和 16 条父会话结果通知；每次输入均为 4 条消息，词表系统前缀
  为 338177 字符。续问附带宿主固定的发送者标识，除此之外归一化当前问题后输入一致。
  持久日志保留全部 16 个原始问题和 14 个成功回答。
- 插件类型检查、完整回归和隔离安装测试通过；部署只更新 10924。

真实宿主验证脚本为 `scripts/va-host-test.mjs`。在独立 `DSH_HOME` 中安装 headless profile，
提供 `DSH_PACKAGE`（官方宿主包目录）与 `OKS_WORKSPACE`（隔离工作区）。
脚本使用进程内确定性适配器，不访问外部模型。

# RFC 0004：产出的时间线——产物自述、保活清理与显式保留

- 状态：**已完成**。两处相对原计划的降级都记在下面（都是上游边界驱动的）。阶段 1（产物自述）、2a（状态与清单）、2b（服务端接口的宿主侧）、
  3（保活清理）、4（右侧栏页签与 profile 装配）都落在 `feat/artifact-timeline` 上，
  issue 上有逐阶段汇报；**页签的真实行为待重启验证**。本文件是变更计划，
  当前事实以 `main` 上的代码与 `README.md` 为准。
- 立项：<https://github.com/hh9527/dsh-oks/issues/17>（档 3：issue 跟踪 + 本 rfc 单独合入 + 实施在分支上）
- 分支：`feat/artifact-timeline`
- 创建日期：2026-10-12
- 关系：承接 [`rfc/0003`](./0003-echarts-rendering.md)——图与报告如今都是落盘的产物；
  本文把"落盘"从**一个临时落点**变成**工作区的产出层**。不改渲染与报告形态。
- 前置观察：
  - 真机 31 个会话向 `.data/` 写了 **680 个文件 / 14 MB / 4 天**（其中一天 425 个），
    而里面**没有任何生命周期概念**：没有清理、没有保留、没有"哪批属于哪次"的痕迹；
  - 人能看的东西（39 张图 + 10 份报告）与内部制品（138+ 个查询结果）混在同一个平铺目录里；
  - `present` **只记路径、不拷贝文件**。所以"清理"这件事在任何保留概念出现之前都不能做——
    否则会砸掉用户手里的交付物。

## 实施中的一处降级：页签改调我们自己开的同源端点

原计划让页签调**我们自己的 Remote namespace**（`oksArtifacts` 的 `list` / `pin` / `unpin`）。
实施时撞到上游的边界：**Typert 生成器目前不支持第三方 Remote**——它按包名核对 `@Remote` 的
装饰器出处，要求那个包是 workspace 里 `packages/*` 下的注册包（协议包在 `node_modules` 里，
两条路都不满足）。现场两句话：生成期 `publishes Remote artifacts but has no Remote methods`；
运行期 `typert-loader: … parameter codec has no create() factory`。

中间试过"插件写清单文件、页签读文件"（`webServer` 那条路当时还没看清）。**最终形态**是插件在
宿主的 web 服务上开两条**同源端点**：

```
GET  /oks/artifacts?sessionId=…            清单
POST /oks/pin                              保留 / 取消保留
GET  /oks/download?sessionId=…&file=…      下载一份报表（字节端点，带 attachment 头）
```

点条目看产物不走端点：界面用资源地址 `dsh-resource://file/session/<sid>/<路径>` 让**宿主的文件页签**
在右栏新开一个页签打开它（格式与文件面板一致），所以插件不需要交出产物内容。

于是前端不读文件、不碰工作区布局：清单是插件知道的事实，问它最直接；保留是机械操作，直接落
后台（不经过 agent）。上游若放开第三方 Remote，把这两条端点换成 Remote 方法即可，界面不动。

## 实施中收敛的一处口径：先只把报表算制品

起初把图与报告都算制品。用过一轮之后收敛为：**当前只有报表算制品**——图是报表里的图（报表渲染时
把它内联成 SVG），查询结果是内部制品，两者都不进清单、也不能被保留。`VISIBLE` 就是这条口径
（`/\.report\.html$/`）。制品同时多了一个**精确分类**（`category`：周报 / 月报 / 即时分析…，
写在自述里、进清单、界面显示在大类图标旁边），大类仍由 `kind` 表达、用图标呈现。

## 决策

工作区多一个**产出层**，七件事一起定：

1. **落点**：三类产物统一落在 `artifacts/`（`refactor!` 已落地：`.data/` → `artifacts/`）；
2. **自述**：每个产物把"自己是什么"写在文件里——报告用 `<meta>`，图用 SVG 自带的 `<title>` 与
   `<metadata>`；**标题永不为空**，agent 没给就由工具按 kind 与维度/度量造一个可读标题；
3. **保活**：未加星的产物在**产生或最后一次被使用**之后 **60 分钟**内保证存在（MVP 固定值，
   暂不做配置项）；过期之后由**懒惰清理**删除（插件被调用时顺带做，没有定时器）；
4. **保留**：`pin` 是**状态**，由人显式发起（agent 代行的也算人发起）。**文件不搬移**——
   产物就留在 `artifacts/` 里，pin 只让清理跳过它；
5. **状态与清单由宿主半边拥有**：条目与保留记在工作区的一份 **sqlite** 里
   （`.oks/state.db`，用插件已有的 `node:sqlite`，零新依赖）。清单是投影，**永远能从
   `artifacts/` 与产物自述重建**；保留是唯一的真状态。
6. **通道是我们自己的服务端接口**：宿主半边用 `TypertRemoteService` 暴露一个 namespace
   （`list` / `pin` / `unpin`），页签通过 `ctx.remote.<ns>` 调它。**浏览器半边拿不到 sqlite、
   也拿不到文件系统**，它只能渲染与调用这条接口——这正是"清单与界面都由我们提供"的完整形态；
7. **界面**：右侧栏新增"产出"页签（我们自己的 client 包）——`[近期]`（滚动 24 小时，默认展开）＋
   窗口外按**用户本地日历日**折叠；每条是双行块（标题 ／ 类型 · 时间）＋ 保留标志；
   "只看保留"是过滤器。

**只有两类产物对人可见**：`.chart.svg` 与 `.report.html`。查询结果（`.query.json`）是内部制品——
它继续落盘、继续被 `oks_jaq_result` 读取，但不进清单。

## 为什么改为这条路线

1. **今天没有生命周期**。680 个文件里没有任何东西告诉人"哪批属于哪一次"，也没有任何东西会消失；
   工作区只会越用越乱，而人能看的东西被埋在内部制品里面。
2. **交付物是路径引用**。`present` 只记路径，所以清理必须先有"保留"这个**显式**概念，
   否则就会出现"文件还在、用户卡片点不开"这种最糟的组合。
3. **自述胜过索引**。元数据写在文件里，产物被复制、转发之后仍然说得清自己是什么；
   清单可以随时从目录与产物重建，不需要为"老产物"做迁移。
4. **保留由人发起**。默认不保留，系统的责任就只剩一条：**你在用的时候它在**。
   于是不需要猜重要性，不需要自动抽取，也不需要为"是不是该留"做任何判断。
5. **可见面收窄**。人对产出的兴趣只在图与报告；把内部制品挡在外面，清单才可能短到一眼扫完。
6. **制品是我们的概念，不是文件系统的概念**。页签不接触工作区布局，只消费我们自己的接口——
   布局以后怎么变，界面都不用跟着改。

## 实施范围

### 阶段 0（已落地）：仓库布局

- `packages/dsh-oks`（现有包）+ `packages/dsh-oks-ui`（新 UI 包，包名 `@local/dsh-oks-ui`）；
- profile 的 `link:` 指向**包目录**（现在链的是仓库根）；`install-preset.sh` 跟着改；
- 一次机械搬迁，不含行为变更。先做它，是因为 profile 的 `link:` 要指向包目录，
  否则写 UI 包时 `link:` 得改两遍；搬迁落在 `main` 上（纯布局），功能实施才走分支。

### 阶段 1：产物自述（服务端）

- 报告：在 `<head>` **最前面**放一行 `<meta name="dsh-oks-artifact" content="<JSON>">`；
- 图：紧跟 `<svg>` 开标签插入 `<title>` 与 `<metadata>`（同一份 JSON）；两者都不参与绘制；
- 字段：`title` / `kind` / `at` / `source`（基于查询结果 或 agent 自填）/ `name`（文件名里的标识）；
- 标题兜底：没有 `title` 时按 kind 与维度/度量造一个可读标题（规则在实现里写死并断言）。

### 阶段 2：状态、清单与我们的服务端接口

- **sqlite**（`.oks/state.db`）：条目（`name` / `kind` / `at` / `title` / `source`）＋ `pinred`；
  写入时机：产物落盘、pin / unpin、清理之后；**能从 `artifacts/` 与产物自述重建**；
- **remote namespace**：`TypertRemoteService` + `@Remote` 方法 `list` / `pin` / `unpin`；
- **生成产物**：`@deepseek-ai/dsh-typert-generator`（已发布）作为 devDependency，
  构建时产出 `lib/typert.host.js` 与 `lib/typert.remote-client.js`；**锁 DSH 版本**；
- **装配**：宿主半边在 preset 里，而 `dsh-typert-loader` 支持显式 `packages` 配置来覆盖
  "嵌套在另一个 Loader 配置项之下"的插件——profile 里加这一行让我们的生成产物被注册；
- **最小验证**：先用一个最小 tab（只显示条数与一个 pin 开关）证明"页签 → 我们的接口 → sqlite"
  这条通道真的通，再铺列表；
- 保留：**不进工具面**——界面上点图钉（走插件端点）。只读的清单动作留在工具面（`oks_artifacts`）。工具描述要写清这条区分：
  **`pin` = 长期保留、不受保活清理影响；它不改条目在列表里的位置**（界面上的标志叫"已保留"，
  图标用 ★ 或 🔒，不用图钉）。

### 阶段 3：保活与清理（服务端）

- 判据下限：文件名里的 `<时间>`（产生时刻）；加分项：**最后一次被使用**（读回结果、被报告引用、
  页签预览都算）——它只会让保活**更长**，不会更短；
- 触发：写产物之前清一次（按分钟节流）。插件只在被调用时活着，所以不需要守护进程；
- 范围：只清**插件写的 + 过了保活 + 未加星**的（未加星以 sqlite 为准）；
  **认不出的文件既不清也不显示**；
- 留痕：日志一行 + 回执一句（"清理了 N 个过期条目"）；
- 提供一个"先看会删什么"的动作（dry-run）。

### 阶段 4：右侧栏"产出"页签（客户端）

- 形态：`@local/dsh-oks-ui` 向 `sidebarRightTabs` 注册一个 tab 类型。**不改右栏外壳**，
  也不替换现有页签（"只留我们的"是 disable 那两条 entry 的事）；
- 数据：`ctx.remote.<我们的 namespace>.list()`；**不列目录、不解析产物文件**；
- 列表：`[近期]`（滚动 24 小时，默认展开）＋ 窗口外按**用户本地日历日**折叠。两者是两个独立的轴：
  进不进 `[近期]` 由滚动窗口决定，属于哪个日期组由本地日历日决定；**保留只改状态，不改分组**；
- 每条：双行块（标题 ／ 类型 · 时间）＋ 保留标志；"只看保留"是过滤器；空状态一句话；
- 列表上的保留开关：走同一个 namespace 的 `pin` / `unpin`（通道已经在，属于可选增量）；
- 打开产物：交给现成的"文档预览"页签（那里认的是文件路径，与我们这层无关）；
- 装配：client 包挂在 **profile 顶层**——`dsh-client-modules` 只扫描主 loader 的 entries，
  写在 preset 里的 `dsh.client` 永远进不了页面模块清单。

## 里程碑

（在 issue 上按此汇报）

- **M1 元数据落地**：图与报告都能从文件里读出元数据，标题永不为空；
- **M2 通道打通**：最小 tab 能通过我们的接口列出条目并切换保留，状态落在 sqlite 里；
- **M3 保活生效**：干净工作区里"产生 → 过期消失 → 留痕"这条链走通，加星的不动；
- **M4 页签上线**：真机右栏里看得见、点得开、保留得动。

## 验收

- **M1**：图（有标题 / 无标题两种）与报告都能读出 `title` / `kind` / `at` / `source`；
  无标题时工具造的标题可读；
- **M2**：最小 tab 列出条目；`pin` 之后 sqlite 里那一行为真、`unpin` 之后为假；
  删掉 sqlite 再触发一次 → 能从目录与产物自述重建条目（保留状态随之丢失，这是预期）；
- **M3**：把保活配成 1 分钟（临时改常量），写两批 → 第二批写入时第一批过期消失且留痕；
  加星的那条不动；认不出的文件不动；
- **M4**：真机打开右栏——刚生成的两类产物出现在 `[近期]`、标题正确、保留状态正确、
  过滤器与日期分组正确、空状态合理；
- **主链（一个干净工作区）**：产生 → 出现在 `[近期]` → pin → 滚出窗口后进日期组 →
  未加星的过期消失、加星的还在。

## 待探问题

1. **生成器在第三方仓库里的用法**：`@deepseek-ai/dsh-typert-generator` 的输入与输出、
   如何在构建里跑、以及**怎么锁 DSH 版本**（生成产物与 DSH 版本耦合，升级要重跑）；
2. **客户端半边能否加载**。这是我们历史上放弃过的半边（当时挂在 preset 里，`dsh.client`
   不进页面模块清单）。本方案要求它是 profile 顶层 entry——**阶段 4 动工前先验这一条**；
3. **`dsh-typert-loader` 的显式 `packages` 写法**：我们的宿主半边在 preset 里，
   要靠它才被注册进运行时注册表；
4. **client 包的构建与依赖**：React 与 `dsh-client-ui-*` 的依赖与打包形态
   （bundle 由宿主侧 `dsh-client-modules` 出，但包的 exports 与依赖要先对齐）；
5. **`.oks/` 的边界**：状态写在 `artifacts/` 之外（产物会被清、状态不能），
   于是"插件只写 `artifacts/`"这条不变量变成"只写 `artifacts/` 与 `.oks/`"——有意扩一条；
6. 标题兜底规则的措辞（按 kind 与维度/度量怎么造）。

## 风险与边界

- **生成产物跟随 DSH 版本**：升级 DSH 可能要求重跑生成、甚至改接口写法（这是选 remote 的
  主要代价）；
- 保活以下限（产生时刻）为准时，**跑得比 60 分钟还久的会话可能失去自己早期的结果**（可重查；
  "最后一次被使用"就是缓解这一条）；
- **`unpin` 不是不可逆删除**，但它解除保护：已经过了保活的那条，在下一次清理时就会走；
- 清单与目录可能短暂不一致（外部删了文件、或另一实例在同一工作区里写）——
  **以目录与产物自述为准重建**，清理与页签都不依赖清单的正确性；
- 并发：同一个工作区可能被另一个 dsh 实例同时使用；保活下限保证了 60 分钟内不会误删；
- **明确不做**：分享（前提是已保留，另立项）、归档清单视图（"保留的显示 2 天"这条截断等它上线
  再启用）、把 `.query.json` 暴露、替换右栏外壳、把本插件顶到 profile 顶层（那会带来全局工具注册）、
  内嵌字体、自动生成 PDF。

# RFC 0012：统一知识与数据加工入口，显式声明资源和路径

- 状态：**已实现，待真机验收与合入**。
- 创建日期：2026-10-16。
- 实现期命名决策：统一工具命名为 `oks_jaq`；下文原拟定名称 `jq_transform` 均对应此入口。
- 关系：在 [RFC 0010](./0010-knowledge-jq.md) 与 [RFC 0011](./0011-projection-pattern.md) 的基础上，合并 `kq` 与 `jq_transform`，统一资源访问、投影和文件路径语义。

## 一、动机与范围

当前知识访问和数据加工采用相同的 jaq 引擎，却分别暴露为 `kq` 与 `jq_transform`。
纯 JSON `project` 已用于知识访问，数据加工的简单投影仍须写 jq 文件或使用另一套 `pick`。
数据加工始终接收具名输入对象，即使只有一份数组，也需要通过 `.fact` 等名字访问；
文件路径又同时接受短文件名和工作区相对路径，调用方要记住不同工具的隐式目录。

拟收敛为一个 `jq_transform`：**声明输入资源，选择 project 或 jq，查看或保存结果**。
单输入直接得到值，多输入显式命名；路径采用相对工作区根目录的完整名称，插件负责校验，不补写目录。

本次包括：

- 将 `kq` 并入 `jq_transform`，以显式内置资源访问知识图。
- 增加 `project`，将 `inputs` 改为 `input`，将 `byFile` 改为 `jq: { src }`。
- 用文件资源的默认视图与 `#meta` 视图区分数据和描述／来源链，取消输入 `root` 与输出 `pick`。
- 统一插件中所有文件路径参数和回执的表达，覆盖 `.work/` 文件工具、jq 程序、报告正文和资产引用。
- 补齐投影及知识参与加工时的来源链记录。

按新契约直接实现，不保留旧参数、短文件名或 `kq` 工具别名。
本次不增加批量保存、加工链 DSL、图表 `src + root`，也不补写领域知识内容。

## 二、统一工具契约

```ts
type Input = string | Record<string, string>;

type TransformArgs = {
  input?: Input;
  project?: ProjectRule;
  jq?: { src: string };
  save?: { name: string; motivation: string };
};
```

`ProjectRule` 与 `createProjector` 沿用 RFC 0011 的纯 JSON 规则和公共函数。

| 参数组合 | 行为 |
| --- | --- |
| 省略 `input` | 输入值为 `{}`，可以运行无外部输入的程序 |
| `input` 为字符串 | 输入值就是该资源的可见值，直接作为 `.` |
| `input` 为映射 | 逐项解析资源，输入值为「名字 → 可见值」的对象 |
| 给出 `project` | 对输入值执行 JS 投影，恰好产生一个值 |
| 给出 `jq` | 读取 `jq.src` 指向的程序文件，对输入值执行 jaq |
| 两者均省略 | 恒等处理，原样返回输入值 |
| 两者同时给出 | 参数错误，在读取资源或执行程序前拒绝 |
| 给出 `save` | 将最终结果物化为封装，并记录完整来源链 |

显式 `null` 不表示省略；非法参数明确报错。命名映射的值只能是资源字符串，名字不能为空；
名字按字面对象键处理，允许同一资源出现在不同名字下。空映射与省略输入均得到 `{}`。

固定执行顺序为：参数校验 → 解析资源和可见值 → 组装输入 → project／jq／恒等处理 → 查看或物化。
`project` 与 jq 接收相同的输入形状，资源解析不根据加工方式改变形状。

## 三、资源与可见值

### 资源表

| 资源字符串 | 可见值 |
| --- | --- |
| `knowledge://` | 当前工作区完整知识图；顶层是 key → 带 `type` 条目的 dict |
| `.oks/data/<name>.def.json`、`.qres.json`、`.tr.json`、`.ctx.json` 等封装路径 | 封装的 `.data` |
| 上述文件路径加 `#meta` | `{ meta, origin }`，不含 `.data` |
| 可读取的图、表和报告资产路径 | 资产统一读模型的 `.data` |
| 上述资产路径加 `#meta` | 统一读模型的 `{ meta, origin }` |

文件必须位于允许读取的工作区目录，且能按资产类型解码为 `{ meta, origin, data }`。
后缀用于识别资产类型，内容仍须校验；任意 JSON 或 `.work/` 文本不因具有 `.json` 扩展名而成为数据资产。
类型后缀沿用实际产物命名，本 RFC 不重命名现有文件。

`#meta` 是工具协议中的视图选择符，不是实际文件名，也不是 jq 路径。
解析时先分离选择符，再校验文件路径。此处只提供默认数据视图和 `#meta`；未知或重复选择符明确报错。
作为该协议资源引用的文件路径保留 `#`，不提供同名真实文件的歧义解释。
`knowledge://` 是精确匹配的内置标识；本轮不定义 `knowledge://#meta` 或网络资源读取。

### 数据边界

普通文件输入只能得到 `.data`，`#meta` 输入只能得到 `{ meta, origin }`。
工具内部为校验和溯源读取完整封装，但完整封装不会作为另一种输入视图交给程序。
需要同时分析两部分时，显式命名两份资源：

```json
{
  "input": {
    "fact": ".oks/data/20261016T090000Z-facts-a1b2c3d4.tr.json",
    "provenance": ".oks/data/20261016T090000Z-facts-a1b2c3d4.tr.json#meta"
  },
  "jq": { "src": ".work/explain.jq" }
}
```

取消 `root` 后，封装内的选择统一由 `project` 或 jq 完成。
普通输入不会再暴露 `.data` 外壳：查询结果的 `.` 是 `{ rows, columns }`，所以程序从 `.rows` 开始；
若加工结果本身是数组，则直接使用 `.[]`。传入命名映射时才使用 `.fact.rows` 或 `.fact[]`。

图、表和报告继续使用现有统一读模型；报告 `.data.structure` 仍是机械缩水后的结构，
`.data.assets` 与 `.data.items` 的含义不变，本次不引入新的报告读取视图。

## 四、文件路径统一

插件接收的文件路径统一为**相对工作区根目录的完整路径**，采用 `/` 分隔：

- jq 程序：`.work/analysis.jq`。
- 报告正文：`.work/article.xhtml`。
- 数据材料：`.oks/data/<完整文件名>`。
- 图表或报告：回执中实际给出的 `.oks/figures/...` 或 `artifacts/...` 路径。

插件不为 `analysis.jq` 补 `.work/`，不剥离调用方传入的目录，不去除首尾空白来猜测文件名，
也不展开 `~` 或环境变量。短文件名、绝对路径、反斜杠、`.`／`..` 路径段等不符合协议的写法明确报错。
内部允许解析绝对位置及真实路径以做边界检查，但这不改变对外资源名称；符号链接也必须通过真实目录边界校验。
创建文件时同时校验目标父目录，防止借目录链接越界。

文件操作权限按用途保持区分：

- `work_write`、`work_read`、`work_edit`、`work_delete` 只操作 `.work/` 内的文件。
- `jq.src` 只读取 `.work/` 内满足现有扩展名和大小要求的 jq 程序。
- `articleFile` 等正文参数只读取 `.work/` 内对应类型的文件。
- 数据资产仍按既有可读目录和类型校验；渲染工具的 `src` 同样使用完整相对路径。

`work_list` 和文件操作回执返回可直接复制给其他工具的工作区相对路径。
目录列表请求用显式 `.work/`，替代把 `.` 隐式解释为代码目录的写法。
`save.name` 等产物标识仍是标识，不是文件路径；工具按命名规则创建文件，返回实际完整相对路径。
报告内部的 `src://<key>` 等内联资源引用也不是文件路径，继续按其自身协议解释。

## 五、知识装载与执行

知识的首个访问示例变为：

```json
{
  "input": "knowledge://",
  "project": { "guide": "*" }
}
```

这与 `jq_transform({})` 区分：空调用得到空对象，读取知识必须显式声明资源。
工具与 skill 提示词给出这份可复制的入口，领域词条和业务语义继续由知识声明。
撤下 `kq` 后，同步其调用示例和所有面向 agent 的访问指引；
服务协议中的 `info(key)` 是模型服务接口，不应被引导条目描述成 agent 可以直接调用的工具。

知识仍按模型内容哈希与 domain 共享初始化，并在独立知识 WTI 实例中保留已解析值。
工具合并不等于合并知识和计算器的 Wasm 实例：

- `project` 直接处理宿主中已装载的知识，不经过 Wasm。
- 单个 `knowledge://` 输入执行 jq 时，复用知识实例已解析文档的 handle。
- 命名输入或知识与文件混合输入，先在宿主组装值，再交给数据计算器执行；
  本轮允许这条路径重新序列化组合输入，不扩展多文档 handle ABI。
- 文件输入与无输入程序使用数据计算器；现有超时、取消和实例失效恢复规则保持。

单资源知识路径继续保证反复查询不重新解析知识；混合路径的额外组装成本是本轮明确的边界。

## 六、物化与来源链

`save` 继续接受单个 `{ name, motivation }`，输出仍为 `.tr.json` 封装，回执返回 `{ asset, bytes }`。
JS 投影和 jq 加工都可以保存；探索而未保存的调用仍只留运行日志。

来源链必须记录实际执行过程：

- 输入资源原文及默认／`#meta` 视图，并区分单输入、命名输入与无输入的形状。
- 文件输入对应的上游根节点和完整来源链，按现有节点身份合并共享祖先。
- 加工方式：project 保存完整 JSON 规则；jq 保存实际读取并执行的源码及完整相对文件路径；
  恒等处理记录为恒等操作。project 不伪装成一段未实际执行的 jq。
- 本次动机、值流输出数，以及现有操作身份信息。

程序可见区域与溯源继承是两件事：普通文件输入只看到 `.data`，来源链仍完整继承；
`#meta` 参与加工时也必须记录原资产与视图，不能因为只读元数据而失去上游。
单输入不得在程序可见值之外暗加一层具名对象；内部来源绑定所用标识必须与对外输入形状明确区分。

知识没有文件封装的上游根，拟增加 `knowledge` 来源节点，记录资源标识、实际模型内容哈希、domain 与发现契约 revision。
同一知识身份可被多个命名输入共享，节点引用仍遵循现有记录身份规则。
来源记录不复制整份知识图，不声称能从哈希还原知识或复现执行；其目的是解释使用了哪一版知识。
知识与文件混合加工时，两类来源都进入同一来源链。

需要同步来源节点类型、校验、易读视图及报告装配：
project 规则随来源链保留，jq 源码继续在报告中集中提取为共享 assets，知识身份节点也随链保留。
从报告内联代码恢复方法时，仍须携带实际源码，外部文件路径本身不能代替源码。
本次不保存通用中间输出，也不改变报告中 figure／span 的引用和数据溯源规则。

## 七、结果与错误

- project 和恒等处理各产生一个值；jq 沿用值流语义：一个值原样、多个值收为数组、零个值收为 `[]`。
- 查看结果统一返回 `{ ok: true, data }`；不再因知识或文件输入使用不同的数据回执形状。
- 查看结果沿用 16 KiB 回执预算。超限只返回错误，提示用更精确的 project 或 jq，不返回半份数据。
- 保存成功返回 `{ asset, bytes }`，结果保留在文件里，不受查看回执大小限制；既有物化约束保持。
- jq 求值达到现有输出上限时仍视为不完整，保存必须失败。投影不经过 jq 引擎，但其查看结果同样受回执预算约束。
- 加载／编译诊断使用传入的完整程序路径并保留行列；运行时错误沿用 Rust 格式化时最多 4 KiB 的诊断预算与截断标记。
- 文件不存在、路径越界、封装不合法、选择符错误和参数错误分别指出具体资源或参数位置；输入说明只附名称、资源与有界形状摘要。

## 八、调用示例

单输入直接探测形状：

```json
{
  "input": ".oks/data/20261016T090000Z-facts-a1b2c3d4.tr.json",
  "project": "$shape"
}
```

读取来源链摘要：

```json
{
  "input": ".oks/data/20261016T090000Z-facts-a1b2c3d4.tr.json#meta",
  "project": { "meta": "*", "origin": { "root": "*", "nodes": "$shape" } }
}
```

关联知识与数据并保存：

```json
{
  "input": {
    "fact": ".oks/data/20261016T090000Z-facts-a1b2c3d4.tr.json",
    "knowledge": "knowledge://"
  },
  "jq": { "src": ".work/label-facts.jq" },
  "save": { "name": "labelled_facts", "motivation": "按知识声明为事实数据补充标签" }
}
```

示例文件名用于说明路径形状；实际调用原样使用工具回执给出的路径。
jq 源码先通过 `work_write` 写入 `.work/label-facts.jq`，再把同一路径传给 `jq.src`，无需换算。

## 九、实施与验收

实施时一并更新工具 schema、路径解析、资源读取、执行路由、来源链及报告处理、README、skill 与冒烟脚本。
参数 schema 必须通过实际宿主支持子集的校验及 SDK 类型生成检查，尤其覆盖 `input` 的字符串／对象联合与嵌套 `project`。

| 验收场景 | 期望 |
| --- | --- |
| 单输入数组／查询结果／命名输入 | 分别直接看到数组、`{ rows, columns }`、具名对象；project 与 jq 形状一致 |
| 普通路径与 `#meta` | 分别只能读数据、描述与来源链；读取其他区域须显式声明另一份资源 |
| project 的递归、缺失键、null、字面键、`$shape` | 与公共函数契约一致，输入不被修改 |
| 省略输入、空映射、恒等处理、显式 null、互斥参数 | 结果或报错符合第二节，非法参数在执行前拒绝 |
| `.work/x.jq` 从写入、列表到执行和诊断 | 使用同一个完整相对路径；短名、越界、目录链接逃逸等均拒绝 |
| 单知识连续访问与并发首次访问 | 复用知识装载及已解析文档，不因工具合并退化 |
| 知识与文件混合 jq、JS 投影保存 | 数据结果正确，两类来源完整，规则／源码与实际操作一致 |
| 单输入与命名输入保存后进入报告 | 输入形状、来源视图、project 规则、共享上游和知识身份均保留 |
| 大结果、运行时大值错误、编译错误 | 输出预算与错误截断生效，保存拒绝残缺结果，编译定位完整 |
| 工具注册与所有提示词示例 | 只暴露统一入口，示例可直接调用，路径与知识访问方法一致 |

实现已在隔离环境构建和验收；真机体验前按仓库纪律单独告知运行产物更新。

# RFC 0006：清单的权威在库里——产出时记账、读路径不碰文件、用户可主动删除

- 状态：**草案**（待评审；评审通过后本文件单独提交合入，实施另开分支）。本文件是变更计划，
  当前事实以 `main` 上的代码与 `README.md` 为准。
- 立项：<https://github.com/hh9527/dsh-oks/issues/20>（档 3：issue 跟踪 + 本 rfc 单独合入 + 实施在分支上）
- 分支：`rfc/0006-artifact-ledger`（本文件）→ 实施分支 `feat/delete-artifact`（阶段 1）、
  `feat/artifact-ledger`（阶段 2）
- 创建日期：2026-10-13
- 关系：**修订** [`rfc/0004`](./0004-artifact-timeline.md) 的决策 5（"清单是投影，永远能从
  `artifacts/` 与产物自述重建；保留是唯一的真状态"）与决策 3 的清理实现。不改产物形态、
  不改渲染、不改读数据的 jq 那条路。
- 前置观察：
  - 现场三次"点开右侧栏「产出」页签，清单是空的"，过一会儿或刷新页面又回来，难以复现；
  - 根因不在某一条容错，而在**读路径在做写**：`GET /oks/artifacts` 每次都
    `begin → upsert 全部行 → 按目录删行 → commit`。列一份清单要拿写锁、要删数据。
    界面每 4 秒轮询一次（每个页签），也就是每 4 秒一个写事务；
  - 于是"清单空/少"有三个互不相干的来路：`artifacts/` 一时看不见、某个文件的头读不出
    （正被写入、正好被清理掉）、状态库撞上写锁。三者都表现为"读不到"或 400；
  - 阶段 0（止血，已合入 `main`）：在读路径上一处一处补——只删"文件真的不在"的行、
    逐文件容错、`busy_timeout = 2s`、界面保留手上的清单并短等重试。它让现象消失，
    但语义没变：读路径仍然是写路径；
  - 用户的"删除"目前只有一条路：等 60 分钟的保活。**没有"现在就不要"这个动作**。

## 决策

一句话：**数据库是清单的登记簿，文件是登记簿指向的 payload；清单路径一个字节的文件系统都不碰。**

1. **账本是清单的权威**。`.oks/state.db` 的 `artifacts` 表就是清单本身，`SELECT` 即清单；
   `GET /oks/artifacts` 与 `oks_artifacts` 工具都只做这一件事。
2. **读路径零文件系统接触**。读 = `openState` → `ensureLedger`（仅在表为空时做一次收养）→
   `SELECT`。不 readdir、不读文件头、不开写事务、不删行。
3. **产出时内存记账，不解析文件**。产出方本来就有元数据：`saveArtifact` 先造
   `meta = { name, kind, at, title, category }`、再 `embedArtifactMeta` 把它写进产物、
   再按内容哈希定文件名。所以记账直接用**同一个 meta 对象**，不从文件里读回来——
   读回来还要解一遍 XML 转义、还要赌 `<head>`/`<svg>` 的形状、还有"标题空或解析失败就
   不写行"这条隐性失败。`saveArtifact` 把 meta 作为返回值带出来；工具层一次调用里做
   **「原子落盘 + 记账」**，记账失败就把文件删掉、整个调用失败（"有文件必有账"）。
4. **原子落盘**：写 `temp` 再 `rename`。半份文件从此不可见——收养、`present`、右栏、下载
   都不必再考虑"读到一半"。这条与清单无关，但它是上面几条的共同前提。
5. **收养与清理只发生在写路径**：
   - `ensureLedger(state, root)`：只在**表为空且目录里有可见产物**时扫一次（新工作区、
     `.oks/` 被删、工作区被 `cp -r` 只带走了 `artifacts/`）。一生只可能发生一次；
   - `reconcileArtifacts(state, root)`：**写产物之前**的懒惰清理里顺带做两件事——补登
     目录里还没有行的可读产物（半份、手放进去的、收养那一刻读不出的），删掉行在而文件
     已不在的条目。它是"漏记"与"人工 rm"的自愈路径；
   - `pruneArtifacts` 改为**遍历行**而不是遍历目录：登记过才知道哪些是我们的，
     于是它不再需要 `OURS` 正则去猜"这是不是我们写的"（材料那边的 `pruneMaterials`
     照旧按目录与命名回收）。
6. **用户可以主动删除**：新增 `POST /oks/delete { sessionId, src }`（与 `pin` 同形，`src`
   仍是 `artifacts/<文件名>`）与界面每行一个 `x`，**只有 `pinned = false` 的条目可点**
   （界面置灰只是提示，服务端同样强制）。校验只看"在 `artifacts/` 内 + 是可见产物 + 登记过"，
   **不要求文件还在**——用户点的是清单上的那一行。顺序是
   **先 unlink（ENOENT 容忍）再删行**：反过来的话，unlink 失败会留下"行没了、文件还在"，
   下一次收养会把它补登回来，用户的删除看起来被撤销。不级联删材料（同一张图可能被别的
   报表引用，材料由保活按龄回收）。**不进工具面**——与 `pin` 同理，删不删由用户在右栏决定。

各时机谁碰什么：

| 时机 | 文件系统 | 数据库 |
|---|---|---|
| 产出产物 | 原子写一份文件 | `INSERT` 一行 |
| 右栏读清单 / agent 列清单 | 不碰 | `SELECT` |
| 保留 / 取消保留 | 不碰（只核对登记与文件名） | `UPDATE` |
| 主动删除 | `unlink`（ENOENT 容忍） | `DELETE` |
| 保活清理（写产物前顺带） | `readdir` + 读未登记文件的自述 | 补登 `INSERT` / 过期与悬挂 `DELETE` |
| 库空后的第一次读 | `readdir` + 读自述（收养） | `INSERT` 多行 |

各事件的收口：

| 事件 | 谁收拾 | 什么时候 |
|---|---|---|
| 状态库被删 | 收养扫描 | 下一次读（表空即触发） |
| 人工删了 `artifacts/` 里的文件 | 清理删行 | 下一次写产物 |
| 产出时记账失败 | 产出方自己 | 当场 unlink + 调用失败 |
| 手放一个报告进 `artifacts/` | 清理补登 / `pin` 时的 reconcile | 下一次写、或点保留时 |
| 半份文件 | 不再产生（原子落盘） | —— |

## 为什么不选另外两条路

- **纯文件为真（清单不落库，库只留保留状态）**：读路径要 readdir + 读 N 个头，瞬时读不到的
  产物会让那一行"闪一下"，而且每次读都在解析。它没有解决"两个真相"，只是把真相放回目录；
  产物本身已经有完整自述，缺的只是"登记"这一件事，不是"更频繁地重读"。
- **报告只进库、不落盘（DB-only）**：`present` 只认工作区里的真实文件
  （`dsh-tool-present` 用 `ctx.fs.lstat` + `type !== 'file'` 判定，参数只有 `path`，没有 URL
  或内容入口），而报告今天的交付就是 `present` 卡片。右栏那条路可以自建
  （客户端有 `ctx.resources.register` 的 protocol provider 机制，`subagent` / `plan` 两个包
  就是这么做的），但 `present` 不松，就得物化、指针文件或改交付口径三选一；而且
  **库丢 = 交付物丢**——报告里的叙述是人写的，重建不出来。留作后续（见"明确不做"）。

## 迁移

- **现有 `.oks/state.db` 不需要迁移**：今天的读路径每次都已把目录对齐过，表里的内容与
  "账本"语义一致（除了本方案新增的 `delete` 路径之外没有新列）。
- 库空 + 目录非空 → 第一次打开时收养（覆盖 `.oks/` 被删、工作区被拷走、直接从别的
  工作区搬来一批报告）。
- 库空 + 目录空 → 什么都不做。
- **保留状态随库**；库丢即丢（与今天一致，`rfc/0004` 已把这条记为预期）。

## 实施范围

### 阶段 1：主动删除（独立可先落）

- `state.ts`：`deleteArtifact(root, src)`——核对"在 `artifacts/` 内 + 可见产物 + 登记过 + 未保留"，
  unlink（文件不在也当删过）→ 删行；返回被删的文件名；未登记、越界、保留中各自明确报错。
- `endpoint.ts`：`POST /oks/delete`（与另外三条同源、同样窄；非 POST 405，缺字段 400）。
- `client.ts`：每行一个 `x`（`pinned = true` 时置灰 + tooltip「先取消保留」），点击后重读清单；
  失败走既有那行提示 + 保留手上的清单。`postDelete` 与 `postPin` 同形。
- 冒烟 + UI 测试 + 文档（README 的"三条端点"改四条）。

### 阶段 2：账本

- `results.ts`：`saveArtifact` 改成原子落盘（`temp` + `rename`）并返回 meta。
- `state.ts`：`recordArtifact(state, file, meta)`；`ensureLedger` / `reconcileArtifacts`；
  `pruneArtifacts` 遍历行；`syncArtifacts` 从读路径退场（它的两个能力拆给收养与清理）。
- `endpoint.ts` / `tools.ts`：清单两处改成纯 `SELECT`；`pinBySrc` 改成"reconcile + 核对登记"。
- `tools.ts`：`oks_report` 那条路走「原子落盘 + 记账」；失败即删文件、整调用失败。
- 收掉阶段 0 的读时三处补丁（`busy_timeout`、界面"保留手上的清单 + 重试"这两条**保留**）。
- 文档：README 的"清单只是投影、随时能从目录与自述重建"改写为"清单是账本；产物自述齐全，
  账本丢了可以由一次收养扫描重建"；`rfc/0004` 的决策 5 由本文件修订。

## 验收

**阶段 1**

- 删未保留：文件与行都没了（回执与 `oks_artifacts` 都能看到）；
- **文件已经不在时**那一行照样删得掉（清单是权威，用户点的是清单上的行）；
- 删保留中的：400，且文件与行都还在；删不存在/未登记的：400；非 POST：405；连删两次第二次 400；
- 界面：`x` 只在未保留时可点；`postDelete` 的请求形状有断言。

**阶段 2**

- **不重新解析**：产出一份标题里带引号与 `&` 的报告 → 库里那行是**原文**、文件里的自述是
  转义后的，两边去编码后相等；
- **有文件必有账**：记账失败时不留孤儿文件（文件被删、调用失败）；
- **读路径不写**：把 `.oks/state.db` 置为只读（或比对 `pragma data_version`）后
  `GET /oks/artifacts` 仍能出清单；
- **收养**：手放一个报告进 `artifacts/` → 下一次写产物时被补登；`pin` 一次也能收养；
- **清理**：人工删掉某个登记过的文件 → 下一次写产物清掉那一行；
- **重建**：删掉整个 `.oks/`（只剩 `artifacts/`）→ 第一次读重建整份清单（保留丢失，是预期）；
- **原子落盘**：`artifacts/` 里不出现 `.part` 之类中间文件；写出过程中（人为在 rename 前
  暂停）读清单/收养都不会看到半份；
- `.smoke-ws` 全量绿；UI 包 `pnpm run check` 绿。

**真机**

- 重启 10923：产出 → 出现在「产出」页签 → `x` 删掉立刻消失 → 保留那条的 `x` 是灰的；
- 观察一段时间，"清单空"不再出现。

## 待探问题

1. **`present` 能不能接受资源地址**（决定"报告默认不落盘"到底能不能做）；右栏自建一个
   `oks` protocol 的实际渲染效果值得先做一次最小实测——两件事一起决定 DB-only 那条路的可行性。
2. `ensureLedger` 要挂在哪些入口：端点与 `oks_artifacts` 带（表空才动），`pin` 走 reconcile；
   下载端点读文件、与库无关，不必带。
3. 记账时要不要顺手记更多（`bytes`、产出它的会话、来源链大小）——现在不记，留位置。
4. 同一个工作区被多个 dsh 实例同时使用时的库并发：止血分支已给 `busy_timeout = 2s`
   （阶段 2 保留），读路径变纯读之后争用更少，但要确认"两个实例同时产出"不会互相删行。

## 风险与边界

- **库成为承重件**：库不可读时清单是空的，直到一次收养把它重建（产物自述齐全，所以能重建；
  **保留真丢**）。这是本方案接受的主要代价。
- **漏记 + 期间没有任何写操作** = 那条产物暂时不显示。所以"清理时补登"不是可选优化，
  它是本方案的一部分。
- **外部改动不再即时可见**：人工放进 `artifacts/` 的报告要等一次写（或一次 pin）才进清单。
  这是有意的——用"清单立刻反映目录"换"读路径不写、不删、不解析"。
- **人工删了文件、下一次写之前**，那一行会短暂存在（点了打不开）。有 `x` 这条正路，
  可接受。
- 报告被删是**不可撤销**的（没有回收站）；未保留的产物本来 60 分钟后也会自己走，
  删除只是"现在"。保留中的产物删不掉，这是保护。

## 明确不做

- **报告只进库**（DB-only / 按需物化 / 指针文件）：等 `present` 与右栏资源协议两条契约确认
  之后另立 rfc。
- 把 `.query.json` / `.chart.svg` 也登记进账本：清单只显示报表这条口径不变
  （`VISIBLE = /\.report\.html$/`）。
- 删除的级联清理、回收站 / 撤销、删除的审计留痕（只写一行日志）。
- 图与报告的渲染形态、`byFile` / `pick` 那套读参数、端点的同源与窄边界。
- 分享 / 归档视图 / 内嵌字体 / 导出 PDF（`rfc/0004` 已列"明确不做"的那些）。

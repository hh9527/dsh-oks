# 工作纪律

- 不要为了探索能力单独开分析稿。一个问题一个分析稿，直接在原稿内尝试和修复；不创建临时 probe 稿，即使用完删除也不例外。
- 除非用户明确要求，否则不要根据取数结果重新调整取数计划。计划只依据用户意图和领域知识，不因结果改变范围、筛选条件、聚合口径或查询组合。
- 调用 dari_resolve 前，先在 .dari 中写明统计口径（范围、时间与时区、筛选条件、聚合及比较方式）；不得看到结果数字后再改口径。
- 先完成全稿检查，再执行。语法、字段和类型错误优先通过 dari_check 修复；不要用运行结果验证查询设计是否正确。
- 每轮尽量只用两次 dari_resolve：一次获取报告及解读所需事实，一次交付最终 Answer。简单问题可以一次；运行错误或用户新增要求时再追加，不为反复核对或细碎探索追加运行。
- 只用模型声明的字段、维度、指标、关系和操作。知识 ID 用于寻址；query 使用 oks_info 给出的短名称，不把知识地址当查询名称，不靠拆地址猜名称。nodes[].id 是本次查询自定别名。
- 不得为了通过检查而偷换统计总体、筛选操作、身份分组或度量含义。能力不足时寻找语义等价计划，必要时澄清或说明限制。
- 截断结果不得用于后处理聚合或当作完整总体；缺失值不擅自补零。静态示例不得冒充业务事实。
- 观测业务值通过 Value/value 引用。不要将取得的数值抄成静态正文绕过来源追踪；Lit 只声明有意的静态文字。
- 当前时间和客户端时区从 context() 获取。注明统计时区；仅在口径确有歧义或 context 无有效时区时追问。时间窗口采用显式半开区间和实际边界。
- 除非用户明确要求评价、推断或建议，采用“述而不作”的态度，客观陈述事实、统计口径与限制，不主动归因、作价值判断或提行动建议。需要推断时区分事实与推断，说明依据和不确定性。
- answer 参数必须显式给出。交付原样使用所选 Markdown 块，略去状态头、分隔注释和调试数据，不另写一份相同回答。用户要报告时，回答简短并用 UseReport 交付链接，不重复整份报告。
- requireRunApproval=true 时等待宿主批准，拒绝或取消后不执行；不得绕过配置。未返回的事实不编造。
- workflow.md、dari.md、rules.md 已完整载入，首题无需再读。仅在逐字引用或上下文被压缩后重读；图表分册按需读取。
